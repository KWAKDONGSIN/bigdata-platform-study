메모리와 계층 구조 — 빠른 것은 작고, 큰 것은 느리다

컴퓨터에는 데이터를 담는 곳이 여러 종류예요. 이 장에서는 이것들을 속도와 크기로 줄 세운 "계층 구조"와, RAM이 모자랄 때 쓰는 "가상메모리", 주소를 바꾸는 "페이지·TLB"까지 배워요. 2023년 기출 Q8, Q9와 올해 새로 나온 가상메모리 내용(HW6, HW7)이 모두 여기 있어요.

5-1. 메모리의 성능을 말하는 다섯 가지 용어

메모리를 비교할 때는 아래 다섯 가지 말을 써요. 자료 4쪽에 나오는 그대로예요. 특히 레이턴시와 대역폭은 둘 다 속도인데 서로 다른 개념이라고 교수님이 강조했어요.

레이턴시

교수님이 녹취에서 레이턴시를 한 번 반대로 말한 곳이 있어요. 자료 4쪽 기준으로 "낮은 레이턴시 = 데이터 접근이 빠름"이 맞아요.

지역성은 앞의 네 개와 성격이 달라요. 앞의 넷은 메모리 장치 자체의 특성이고, 지역성은 프로그램이 메모리를 쓰는 습관에 대한 이야기예요.

시험엔 이렇게 써요

레이턴시는 데이터에 접근하는 데 걸리는 시간으로 낮을수록 빠르고, 대역폭(스루풋)은 단위 시간당 전송되는 데이터 양이다. 휘발성은 전원이 꺼지면 데이터가 소멸하는 성질이며, 지역성은 데이터를 접근할 때 특정 영역과 그 주변을 자주 접근하는 경향이다.

잠깐 확인 — "영상을 눌렀는데 재생이 바로 시작된다"는 레이턴시와 대역폭 중 무엇이 좋은 건가요?

레이턴시가 낮은(짧은) 거예요. 시작까지 걸리는 시간이 짧다는 뜻이에요. 영상이 끊기지 않고 부드러운 것은 대역폭이 충분한 거예요.

5-2. 메모리 계층 구조 ★★★ 시험 필수

컴퓨터의 기억장치는 한 종류가 아니라 레지스터 → 캐시 → 주기억장치(RAM) → 보조기억장치(SSD/HDD) 4층으로 되어 있어요. 이것을 계층 구조(hierarchy)라고 해요. 위로 갈수록 빠르고, 작고, 비싸요.

장치위치소자접근 속도휘발성

꼭 알아둘 세 가지예요.

  • CPU 안에 있는 메모리는 2개 : 레지스터와 캐시. RAM과 SSD는 CPU 밖의 별도 부품이에요.
  • 속도 순서 : 레지스터 > 캐시 > RAM > SSD(또는 HDD). 용량은 정반대예요.
  • 휘발성 : RAM 이상(레지스터, 캐시, RAM)은 전원이 꺼지면 사라지고, SSD·HDD 같은 보조기억장치는 비휘발성(반영구)이에요.

왜 계층으로 나눌까요? 빠르면서 큰 메모리는 너무 비싸서 PC를 100~200만 원에 만들 수 없어요. 그래서 "자주 쓰는 소량은 빠른 곳에, 나머지는 느리고 싼 곳에"로 나눠서 값은 낮추고 속도는 높였어요. 교수님이 말한 이 장의 핵심 문장은 "속도가 빠르면 용량이 작고, 용량을 키우면 속도가 느려진다"예요.

비유 — 교수님의 시험공부

중간고사 범위가 1~7주차 PDF 전체라고 해 봐요. 도서관(SSD)에 모든 자료가 있고, 이번 시험 범위 전체를 책장(RAM)에 꽂아 두고, 지금 공부하는 1주차 자료는 책상(캐시)에 펴 놓고, 지금 푸는 문제의 구체적인 개념은 노트(레지스터)에 적어요. 범위가 좁아질수록 빠르게 꺼내 쓸 수 있고 양은 줄어요.

속도 차이를 숫자로 느껴 보세요. 단위는 1ms = 1,000µs = 1,000,000ns예요. SSD의 20µs는 20,000ns이고 RAM이 50~70ns니까 SSD는 RAM보다 수백 배~수천 배 느려요. (20,000 ÷ 70 ≈ 290배, 200,000 ÷ 50 = 4,000배) 그래서 컴퓨터가 느려지는 병목은 주로 RAM과 SSD 사이에서 생겨요.

2023년 기출 Q8과 HW6 Q1~Q3은 이 표를 그대로 물었어요. 번호는 시험지마다 달라요. 기출은 1 RAM, 2 보조기억장치, 3 레지스터, 4 캐시였고 HW6는 1 레지스터, 2 캐시, 3 RAM, 4 보조기억장치였어요. 번호보다 이름의 순서로 외우세요.

질문답 (이름)
CPU 안에 있는 메모리 2개레지스터, 캐시
접근 속도가 빠른 순서레지스터 → 캐시 → RAM → 보조기억장치
같은 가격 대비 용량이 큰 순서보조기억장치 → RAM → 캐시 → 레지스터

HW6 Q5 "메모리 계층 구조를 사용하는 이유"의 답은 이렇게 써요. 빠르고 용량이 큰 메모리는 너무 비싸서, 속도가 빠르고 용량이 작은 메모리와 속도가 느리고 용량이 큰 메모리를 단계적으로 배치해 정해진 가격 안에서 속도와 용량을 모두 확보하려고 해요. CPU의 계산 속도와 RAM·보조기억장치 속도 차이가 크다는 이유도 함께 써 주면 좋아요.

외우기 팁

"레-캐-램-보" (레지스터, 캐시, 램, 보조)가 빠른 순서이고, 거꾸로 "보-램-캐-레"가 용량 큰 순서예요. CPU 안은 앞의 "레-캐" 두 개예요.

시험엔 이렇게 써요

메모리 계층 구조는 레지스터, 캐시, 주기억장치(RAM), 보조기억장치로 이루어지며, 위로 갈수록 접근 속도가 빠르고 용량이 작으며 비트당 가격이 비싸다. CPU 내부에 있는 메모리는 레지스터와 캐시이다. 빠르고 용량이 큰 메모리는 가격이 매우 비싸기 때문에 제한된 비용으로 속도와 용량을 함께 확보하려고 계층 구조를 사용한다.

잠깐 확인 — 엑셀로 더하기 계산을 하는 중인 두 숫자는 어느 메모리에 있나요?

레지스터예요. CPU(ALU)가 직접 계산하는 값은 가장 빠른 레지스터에 올라와요.

5-3. 캐시와 적중(hit), 실패(miss), 지역성 ★★

캐시(cache)는 레지스터와 RAM 사이의 완충 지대예요. 레지스터와 RAM은 속도 차이가 너무 커서, 가운데 한 층을 더 끼운 거예요. 캐시는 CPU 안에 있고 L1, L2, L3 세 단계로 만들어요. L1이 CPU에 가장 가깝고 작고 빠르며, L2는 L1보다 일반적으로 크고 느리고, L3는 여러 코어가 함께 쓰기도 해요.

CPU가 데이터를 찾는 방식은 이래요. 먼저 L1 캐시에서 찾아보고, 없으면 L2, L3, 마지막으로 RAM으로 내려가요.

용어뜻
캐시 히트
cache hit, 적중		필요한 데이터가 캐시에 있다. 바로 쓸 수 있어요
캐시 미스
cache miss, 실패		필요한 데이터가 캐시에 없다. 다음 캐시 단계나 RAM에서 가져와야 해요
캐시 라인
cache line		캐시와 RAM 사이에서 한 번에 옮기는 데이터 묶음 (예 64바이트). 필요한 한 칸만이 아니라 주변까지 같이 가져와요

캐시가 가득 차면 기존 라인이 교체될 수 있어요. 이 일은 보통 CPU 하드웨어가 자동으로 해요.

비유

책상 위(캐시)에 필요한 책이 있으면 바로 읽어요(히트). 없으면 책장(RAM)까지 가서 가져와야 해요(미스). 책장에서 책을 가져올 때 옆에 꽂힌 책 몇 권도 같이 가져오면 다음에 또 일어나지 않아도 되겠죠? 이게 캐시 라인이에요.

지역성이 왜 중요한지 보여 주는 곳이 여기예요. 프로그램은 데이터를 아무 데나 랜덤하게 읽지 않고, 한 곳을 읽으면 그 주변을 이어서 읽는 경향이 있어요. 이 습관 덕분에 주변까지 함께 캐시에 올려 두면 다음 접근이 대부분 히트가 돼요. 교수님 비유로는 시험공부를 1장 → 2장 → 3장 순서로 하는 것이 지역성이고, 1장 보다가 갑자기 5장, 7장, 2장을 오가는 것이 랜덤 액세스예요.

참고 — 교과서에서는 지역성을 시간 지역성(방금 쓴 데이터를 곧 또 쓴다)과 공간 지역성(쓴 데이터의 주변을 곧 쓴다)으로 나누기도 해요. 이 수업 자료에는 나누어 나오지 않았어요.

참고 — 수업 자료와 기출에는 없는 계산이지만, 캐시가 얼마나 도움이 되는지 감을 잡는 손계산이에요. 평균 접근 시간 = 적중률 × 캐시 시간 + (1 − 적중률) × RAM 시간으로 단순하게 계산하면, 캐시 2ns, RAM 60ns, 적중률 90%일 때 0.9×2 + 0.1×60 = 1.8 + 6 = 7.8ns예요. 적중률이 99%면 0.99×2 + 0.01×60 = 2.58ns로 줄어요. 적중률이 높을수록 빨라져요.

시험엔 이렇게 써요

캐시는 CPU 내부에 있으며 레지스터와 주기억장치의 속도 차이를 줄이는 버퍼 메모리이다. 필요한 데이터가 캐시에 있으면 캐시 히트, 없어서 다음 캐시 계층이나 RAM에서 가져오면 캐시 미스라고 한다. 지역성은 특정 영역과 그 주변 데이터를 자주 접근하는 경향이며 캐시의 효율을 높인다.

잠깐 확인 — 캐시 미스가 나면 데이터는 어디서 가져오나요?

다음 캐시 단계(L2, L3)나 RAM에서 가져와요.

5-4. 주기억장치(RAM) — ROM, SRAM, DRAM, 주소 ★★

주기억장치는 CPU와 직접 데이터를 주고받는 기억장치예요. 프로그램 수행에 필요한 명령과 데이터를 담아요. 요즘은 반도체로 만들고, 크기가 작고 속도가 빠르며 전력을 적게 먹어요. 크게 ROM과 RAM으로 나뉘어요.

비유

SRAM은 칠판에 적은 글씨라서 지우기 전엔 그대로예요(대신 칠판이 비싸고 커요). DRAM은 모래시계처럼 물이 조금씩 새는 컵이라, 주기적으로 물을 다시 채워 줘야 값이 유지돼요(대신 싸고 작게 만들 수 있어요).

왜 캐시는 SRAM이고 RAM은 DRAM일까요? 빠른 SRAM은 비싸서 조금만 쓸 수 있고, 싼 DRAM은 느리지만 많이 쓸 수 있어서 용량이 큰 주기억장치로 알맞아요. 계층 구조의 "빠를수록 작고 비싸다"가 바로 소자(부품)의 차이에서 나와요.

메모리는 번지(주소)가 붙은 칸들의 모음이에요. 기출 Q4에서는 "8비트(=1바이트)가 1워드인 메모리"의 01~10번 주소에 숫자와 글자를 하나씩 넣었어요. 한 번지에 1바이트가 들어가고, 번지 번호는 0부터 세요(과제 HW7도 "0번째부터"라고 안내했어요). 주소가 n비트면 2의 n제곱 개의 칸을 가리킬 수 있어요. 4장의 1-주소 명령 예처럼 주소가 11비트면 211 = 2,048칸이에요.

참고로 VRAM은 그래픽카드용 RAM으로, 데이터를 쓰는 핀과 읽는 핀이 따로 있어서 쓰는 동안 읽을 수 있어요. GPU로 AI 계산을 하면서 더 중요해졌어요.

외우기 팁

SRAM은 Speed(빠름), 캐시. DRAM은 Dense(빽빽, 대용량)·Discharge(방전돼서 리프레시), 주기억장치예요.

시험엔 이렇게 써요

RAM은 임의의 주소에 즉시 읽고 쓸 수 있는 휘발성 메모리이고, ROM은 읽기 전용 비휘발성 메모리이다. SRAM은 플립플롭으로 구성되어 속도가 빠르지만 가격이 비싸고 집적도가 낮아 캐시에 사용되며, DRAM은 콘덴서로 구성되어 주기적으로 리프레시가 필요하지만 저렴하고 집적도가 높아 주기억장치로 사용된다.

잠깐 확인 — 전원이 끊겨도 내용이 남는 주기억장치 종류는 ROM과 RAM 중 무엇인가요?

ROM이에요(비휘발성). RAM은 전원이 끊기면 지워지는 휘발성이에요.

5-5. 운영체제와 프로그램, 프로세스 ★★

컴퓨터의 하드웨어(CPU, RAM, SSD)를 조립한 다음 가장 먼저 설치하는 것이 운영체제(OS, Operating System)예요. Windows, Linux, macOS가 대표예요. 운영체제는 응용 프로그램(엑셀, 게임, 파이썬 등)과 하드웨어 사이에서 둘을 관리해 줘요.

한 줄 정의

운영체제 = 컴퓨터 전원이 켜지면 가장 먼저 시작되는 프로그램으로, 컴퓨터의 자원(CPU, 메모리, 저장장치 등)을 관리하고 여러 응용 프로그램의 실행을 관리하는 시스템 소프트웨어.

운영체제가 하는 일 중 시험에 가장 잘 이어지는 두 가지는 프로그램 실행 관리와 메모리 관리예요. 자료 27쪽에는 관리 대상 7가지가 나와요(프로세스, 작업, 주기억장치, 보조기억장치, 입출력장치, 파일, 보안). 운영체제의 핵심 부분은 커널이고, 항상 메모리에 올라와 있어요. 사용자가 커널을 직접 만지지 못하고 시스템 호출로 부탁해요. 교수님 자료의 비유는 "커피머신을 직접 만지지 않고 바리스타에게 부탁하는 것"이에요.

이제 헷갈리는 세 단어를 구분해요.

용어뜻비유
프로그램저장장치(SSD/HDD)에 보관돼 있는 코드. 정적인 상태레시피 (책에 적힌 상태)
프로세스프로그램을 실행해서 메모리에 올라와 작업 중인 것. 동적인 상태. 운영체제도 하나의 프로세스예요조리 중인 요리

발음이 비슷해서 헷갈리지만 프로세스는 소프트웨어(실행 중인 프로그램), 프로세서는 하드웨어(CPU)예요. 프로그램을 더블클릭하면 프로세스가 돼요. 프로세스는 생성 → 준비(CPU를 기다림) → 실행 → 완료의 상태를 거쳐요(참고).

시험엔 이렇게 써요

운영체제는 컴퓨터 전원이 켜지면 가장 먼저 시작되는 프로그램이며 컴퓨터 자원을 관리하고 여러 응용 프로그램의 실행을 관리한다. 응용 프로그램의 코드가 보조기억장치에 보관되어 있으면 프로그램이라고 하고, 실행되어 메모리에 적재되어 있으면 프로세스라고 한다.

잠깐 확인 — 워드 프로그램을 더블클릭해서 실행하면 무엇이 생기나요?

프로세스예요. 보관돼 있던 프로그램이 메모리에 적재되어 실행 중인 상태가 돼요.

5-6. 가상메모리와 스왑 영역 ★★★ 올해 새로 추가

컴퓨터마다 RAM 크기가 달라요. 노트북은 8GB, 어떤 PC는 16GB나 32GB예요. 개발자가 "4GB용, 8GB용, 16GB용"으로 프로그램을 따로 짠다면 너무 힘들겠죠. 그래서 나온 아이디어가 가상메모리예요.

한 줄 정의

가상메모리 = 사용자의 실제 메모리 크기와 프로세스가 올라갈 위치를 신경 쓰지 않고 프로그래밍하도록, 프로세스에 (거의) 무한한 커다란 메모리 공간을 제공하는 기술. 실제 관리는 운영체제가 해요.

비유

호텔 투숙객은 "내 방이 몇 호든 상관없이 침대와 책상이 있는 내 방"이라고만 생각해요. 호텔 직원(운영체제)이 실제 빈 방을 배정하고 관리해요. 프로그래머가 보는 방 번호는 가상이고, 실제 방은 물리 메모리예요.

가상메모리는 프로세스가 바라보는 영역(가상)과 메모리 관리자가 바라보는 영역(실제 물리 메모리)으로 나뉘어요. 프로세스 여러 개(워드, 파워포인트, 크롬)가 함께 실행되면 물리 메모리는 운영체제 영역과 각 프로세스에게 나눠져요. 운영체제가 서로 침범하지 않게 막아 줘요.

그런데 물리 메모리는 한계가 있어요. 프로세스가 자꾸 더 많이 달라고 하면 어떻게 할까요? 안 쓰는 부분을 보조기억장치로 내보내고 그 자리에 새로 필요한 것을 올려요. 이 내보내는 공간이 스왑 영역(swap area)이에요.

  • 스왑 영역 : 메모리가 모자라 쫓겨난 프로세스(의 메모리)를 모아 두는 저장장치(SSD/HDD)의 특별한 공간. 크기를 사용자가 조절할 수 있지만 너무 작으면 프로그램이 실행되지 못할 수 있어요.
  • 절전 모드(최대 절전): 전원을 끊기 전에 RAM 내용을 통째로 스왑 영역에 옮겨 둬요. 다시 켜면 불러와서 이어서 해요. RAM이 휘발성이기 때문이에요.
  • 스와핑 : 메모리와 스왑 영역 사이에서 내용을 옮기는 일.

2023년 기출 Q9가 이 과정을 렉에 빗대서 물었어요. 40GB짜리 CSV를 16GB RAM 컴퓨터에서 평균 내려는 코드예요.

시험엔 이렇게 써요

가상메모리는 실제 메모리 크기와 관계없이 프로세스에 큰 메모리 공간을 제공하는 기술이다. 프로그램이 사용하는 메모리가 물리메모리(RAM) 용량을 초과하면 일부 데이터가 보조기억장치의 스왑 영역으로 이동하는데, 이를 스와핑이라 하며 접근 속도가 매우 느린 보조기억장치를 계속 사용하므로 컴퓨터가 느려진다. 40GB 파일을 처리하려면 충분한 크기의 RAM 용량을 확보해야 한다.

잠깐 확인 — RAM이 모자랄 때 쫓겨난 데이터가 가는 곳의 이름은?

스왑 영역(스왑메모리)이에요. 보조기억장치(SSD/HDD)에 마련된 공간이에요.

5-7. 페이지, 프레임, 주소 변환 ★★ 계산 문제 가능

운영체제는 메모리를 바이트 하나하나가 아니라 같은 크기의 블록으로 나눠서 관리해요. 가상메모리의 블록은 페이지(page), 물리메모리(RAM)의 블록은 프레임(frame)이라고 해요. 두 블록의 크기는 같아요. 이 크기가 페이지 크기예요(예 4KB = 4,096바이트).

비유

가상주소는 "301호"라는 방 번호이고, 물리주소는 건물 안의 실제 위치예요. 책의 쪽수(페이지 번호)와 그 쪽 안의 몇 번째 줄(오프셋)로 위치를 말하는 것과도 같아요.

핵심 공식은 하나예요. 주소를 "페이지 번호 + 페이지 안의 위치(오프셋)"로 쪼개요.

공식

가상주소 = 페이지 번호 × 페이지 크기 + 오프셋 (페이지 안의 위치)

손계산 순서는 3단계예요. 예는 자료 13쪽의 가상주소 10,000이고 페이지 크기는 4,096이에요. 페이지 테이블은 (페이지 0→프레임 7, 1→2, 2→9, 3→4)예요.

  • ① 나눗셈 : 10,000 ÷ 4,096 = 몫 2, 나머지 1,808. 그러니까 페이지 번호 2, 오프셋 1,808이에요 (2 × 4,096 = 8,192이고 10,000 − 8,192 = 1,808).
  • ② 표 찾기 : 페이지 테이블에서 페이지 2는 프레임 9예요.
  • ③ 다시 합치기 : 9 × 4,096 + 1,808 = 36,864 + 1,808 = 38,672. 이게 물리주소예요.

왜 오프셋은 그대로일까요? 페이지와 프레임은 크기가 같아서 블록 안의 위치는 변하지 않기 때문이에요. 바뀌는 것은 "몇 번째 블록이냐"뿐이고, 데이터의 값은 그대로예요. 달라지는 건 CPU가 찾아가는 주소예요.

한 문제 더 해 봐요. 같은 표에서 가상주소 5,000이면? 5,000 ÷ 4,096 = 몫 1, 나머지 904. 페이지 1은 프레임 2니까 물리주소는 2 × 4,096 + 904 = 8,192 + 904 = 9,096이에요.

시험엔 이렇게 써요

가상메모리는 페이지, 물리메모리(RAM)는 같은 크기의 프레임으로 나누어 관리하며, 가상주소는 페이지 번호 × 페이지 크기 + 오프셋으로 나타낸다. 주소 변환은 페이지 번호만 프레임 번호로 바꾸고 오프셋은 그대로 유지한다. 예를 들어 가상주소 10,000은 페이지 2(오프셋 1,808)이고 프레임 9에 대응되면 물리주소는 9 × 4,096 + 1,808 = 38,672이다.

잠깐 확인 — 페이지 크기 4,096에서 가상주소 8,300은 페이지 몇 번, 오프셋 몇인가요?

8,300 ÷ 4,096 = 몫 2, 나머지 108이에요(2 × 4,096 = 8,192). 페이지 2, 오프셋 108이에요.

페이지 테이블페이지의 RAM 대응 (페이지 → 프레임)이 페이지가 지금 RAM에 있어서 접근 가능한가?
CPU 캐시실제 데이터 (캐시 라인)데이터가 캐시에 있나?
  • 페이지 테이블 : 가상 페이지가 RAM의 어느 프레임에 대응되는지 적은 표예요. 프로세스마다 하나씩 있고(워드, 파워포인트, 브라우저 각각), 보통 RAM에 있어요.
  • TLB : 페이지 테이블에서 자주 쓰는 변환 정보만 뽑아서 캐시처럼 빠르게 보관하는 곳이에요. 실제 데이터가 아니라 "페이지 → 프레임" 정보를 담아요. 찾으면 TLB 히트, 없으면 TLB 미스예요.
  • 페이지 폴트(page fault) : 필요한 페이지가 RAM에 없고 스왑 영역에 있는 경우예요. 운영체제가 스왑 영역에서 RAM으로 적재(스와핑)하고, 페이지 테이블과 TLB를 고친 뒤 다시 실행해요.
외우기 팁

TLB 미스 ≠ 페이지 폴트. TLB 미스는 "빠른 메모장에 변환 정보가 없다"는 뜻이라 페이지 테이블에서 찾으면 돼요. 페이지 폴트는 "아예 RAM에 그 페이지가 없다"는 더 큰 사건이에요.

전체 순서를 그림 하나로 정리했어요. HW7 Q1은 이 그림을 따라가며 사건의 번호를 순서대로 쓰는 문제예요.

TLB → 페이지 테이블 → (필요하면 스왑) → 물리주소 → 캐시 → 메모리. 자료 07 슬라이드와 7주차 교수님 설명을 합친 그림이에요.

2단계도 같은 방식이에요. 물리주소를 알았으면 캐시를 먼저 보고(⑦), 있으면 히트(⑧), 없으면 미스(⑨)라서 메모리에서 읽어 와요(⑩). 교수님은 "주소를 알아야 데이터를 가져올 수 있다. 1단계는 주소, 2단계는 데이터"라고 설명했어요.

자료 20쪽 확인문제도 풀어 보세요. 무엇이 갱신되는지를 묻는 세 문제예요.

상황정답
페이지는 RAM에 있지만 TLB에 주소 변환 정보가 없다페이지 테이블 탐색 → TLB 갱신
주소 변환은 성공했지만 L1/L2/L3에 데이터가 없다RAM에서 캐시 라인 읽기 → CPU 캐시 갱신
필요한 페이지가 스왑에 있고 RAM에 없다OS가 RAM에 적재 → 페이지 테이블 갱신 → 재실행

용어 몇 개를 더 정리해요. 페이지 적재(page-in)는 필요한 페이지를 RAM으로 가져오는 일, 페이지 반출(page-out)은 RAM에서 내보내는 일, 스왑 인/아웃은 스왑 영역과 RAM 사이에서 가져오고 내보내는 일이에요. 페이지 교체는 RAM이 부족할 때 기존 페이지를 내보내고 새 페이지를 놓는 일이에요. 페이지 폴트가 났다고 항상 스왑을 읽는 것은 아니고(새 페이지 할당이나 파일 읽기로 해결되기도 해요), 이 수업에서는 "스왑에 있는 경우"를 다뤄요.

시험엔 이렇게 써요

CPU가 가상주소로 메모리에 접근하면 먼저 TLB에서 주소 변환 정보를 찾는다. TLB 히트이면 물리주소를 바로 얻고, TLB 미스이면 페이지 테이블을 탐색한다. 페이지가 RAM에 있으면 TLB를 갱신하고, RAM에 없으면 페이지 폴트가 발생하여 운영체제가 스왑 영역의 페이지를 RAM에 적재하고 페이지 테이블과 TLB를 갱신한다. 물리주소를 얻은 뒤에는 캐시에 접근하여 히트이면 데이터를 사용하고, 미스이면 메모리에서 데이터를 가져온다.

잠깐 확인 — TLB 미스가 나면 반드시 페이지 폴트가 발생하나요?

아니에요. 페이지가 RAM에 있다면 페이지 테이블을 보고 정상적으로 변환할 수 있어요. 페이지가 RAM에 없을 때만 페이지 폴트가 나요.

이 장 3줄 요약
  • 메모리는 레지스터 → 캐시 → RAM → 보조기억장치 순으로 빠르고 작고 비싸며(CPU 안은 레지스터·캐시), 캐시는 히트/미스, 지역성(주변 데이터도 곧 쓴다)으로 효율을 얻어요. SRAM은 캐시, DRAM은 RAM이에요.
  • 운영체제가 프로그램(저장) → 프로세스(메모리에서 실행)를 관리하고, RAM이 모자라면 가상메모리가 스왑 영역(보조기억장치)을 써서 스와핑이 일어나 느려져요. 해결은 RAM 늘리기예요.
  • 가상주소 = 페이지 번호 × 페이지 크기 + 오프셋이고(10,000 = 2×4,096 + 1,808 → 프레임 9 → 38,672), 주소 찾기는 TLB → 페이지 테이블(없으면 폴트·스왑) → 캐시 → 메모리 순서예요.
