중앙처리장치(CPU) — 컴퓨터의 두뇌가 일하는 법

컴퓨터에서 계산을 맡는 부품이 CPU예요. 이 장에서는 CPU 안에 무엇이 들어 있는지, 명령 한 줄이 어떤 5단계로 실행되는지, CPU가 왜 더 빨라지기 어려운지를 배워요. 2023년 기출의 Q1, Q3, Q6, Q7이 모두 이 장에서 나와요.

4-1. 폰 노이만 구조 — 프로그램이 실행되는 길 ★★

컴퓨터 안에서 프로그램은 세 군데를 차례로 지나가요. 먼저 보조기억장치(SSD나 HDD)에 보관돼 있다가, 실행하면 주기억장치(RAM)에 올라오고, 한 줄씩 CPU로 가서 계산돼요. 이렇게 "CPU + 기억장치로 이루어지고 프로그램을 한 줄씩 실행하는" 방식을 폰 노이만 구조(Von Neumann architecture)라고 해요.

비유

요리 학원을 떠올려 보세요. 레시피 책은 책꽂이(보조기억장치)에 꽂혀 있고, 오늘 만들 레시피만 주방 작업대(RAM)에 펼쳐 놓아요. 요리사(CPU)는 레시피를 한 줄씩 읽으며 요리하고, 중간 결과는 작업대에 다시 놓아요.

왜 이렇게 나눌까요? 보조기억장치는 크고 값이 싸지만 느려서 CPU가 바로 쓰기엔 답답해요. 그래서 지금 필요한 것만 빠른 RAM에 올려 놓고 써요. 전원이 꺼져도 남아야 하는 프로그램은 보조기억장치에, 실행 중인 것은 RAM에 있는 거예요.

2023년 기출 Q3가 정확히 이 흐름을 물어봤어요. 아래 sum.py는 1부터 100까지 더하는 파이썬 코드예요.

1. n = 1; 2. sum = 0; 3. while (n <= 100): 4. sum = sum + n 5. n = n +1
코드 줄무슨 뜻
n = 1n이라는 이름의 상자를 만들고 1을 넣어요 (대입).
sum = 0sum이라는 상자를 만들고 0을 넣어요.
while (n <= 100):n이 100 이하인 동안 아래 두 줄을 계속 반복해요.
sum = sum + nsum에 n을 더해서 다시 sum에 넣어요 (누적).
n = n +1n을 1 늘려요.

실행 결과는 이래요. 시험지 코드에는 화면에 출력하는 줄이 없어요. 하지만 반복이 끝나면 sum 상자에는 1+2+...+100 = 5050이 들어 있어요. 첫 반복만 따라가 보면 n=1일 때 sum은 0+1=1이 되고, n은 2가 돼요.

기출 빈칸은 이렇게 채워요. 보관은 보조기억장치, 적재는 주기억장치, 계산은 CPU, 변수 상자(n, sum)는 RAM 안에 있어요.

폰 노이만 구조는 계산장치(CPU)와 기억장치로 구성되어, 계산장치가 기억장치의 프로그램에서 명령을 한 줄씩 실행하고 계산 결과를 기억장치에 기록하는 방식으로 동작하는 컴퓨터 구조이다. 프로그램은 보조기억장치에 보관되어 있다가 실행되면 주기억장치(RAM)에 적재되고, CPU가 명령을 한 줄씩 가져와 계산한다.

잠깐 확인 — 실행 중인 프로그램의 변수 값 n, sum은 어디에 기억되나요?

주기억장치(RAM)예요. 프로그램이 실행되면 RAM에 올라오고, 변수 값도 RAM의 변수 공간에 기억돼요.

CPU는 반드시 있어야 하는 부품 3가지와, 성능을 높이려고 덧붙인 부품 1가지로 이루어져요. 필수 3가지는 산술논리연산장치(ALU), 제어장치(CU), 레지스터 세트예요.

비유 — 교수님의 시험공부

SSD는 도서관, RAM은 책장, 캐시는 책상, 레지스터는 책상 위에서 필기하는 노트, ALU는 두뇌예요. 도서관에서 필요한 책만 빌려 책장에 꽂고, 지금 볼 책은 책상에 펴고, 계산하는 숫자는 노트에 적는 식이에요.

왜 레지스터와 캐시를 따로 둘까요? ALU는 1초에 수십억 번 계산하는데 RAM이나 SSD는 그 속도로 데이터를 못 대 줘요. 그래서 CPU 가까이에 작고 빠른 메모리를 층층이 둬서 ALU가 기다리지 않게 해요. 속도는 레지스터 > L1 > L2 > L3 > RAM > 디스크 순이고, 용량은 반대 순서예요.

시험엔 이렇게 써요

CPU의 필수 구성 요소는 산술논리연산장치(ALU), 제어장치(CU), 레지스터 세트이다. ALU는 산술·논리 연산을 수행하고, 제어장치는 명령어를 해독하여 제어신호를 발생시키며, 레지스터는 CPU 내부에 있는 용량은 작지만 매우 빠른 메모리이다. 특수 레지스터에는 PC(다음 명령의 주소), IR(현재 명령), AC(누산기), MAR(메모리 주소), MBR(메모리 버퍼)이 있다.

잠깐 확인 — 다음에 실행할 명령이 메모리 몇 번지에 있는지 기억하는 레지스터는?

PC(프로그램 카운터)예요. 책갈피처럼 "다음에 읽을 번지"를 가리켜요.

4-4. 기계어와 명령어 — opcode와 operand ★★

CPU가 바로 알아듣는 말은 0과 1로 된 기계어뿐이에요. 사람은 파이썬 같은 고급언어로 코드를 쓰고, 번역기(인터프리터 등)가 이것을 기계어로 바꿔 줘요. 기계어는 사람이 읽기 어려워서, 거의 1대1로 직역한 어셈블리어로 읽어요.

고급언어 (파이썬)어셈블리어기계어 (16비트)

MOVE R2 31000 0010 0000 0011
ADD R3 R1 R21100 0011 0001 0010
STORE CC R3(번지 CC에 R3 저장)
B = 5 * AMOVE R4 51000 0100 0000 0101
LOAD R5 CC(번지 CC에서 R5로 읽기)
MUL R6 R4 R51101 0110 0100 0101
STORE CD R6(번지 CD에 R6 저장)

파이썬 한 줄이 어셈블리 여러 줄이 돼요. A = 2 + 3 하나가 MOVE, MOVE, ADD, STORE 네 줄이에요. 번지(메모리 주소) 줄은 아래에서 따로 풀어요.

명령 한 줄(instruction)은 두 부분으로 이루어져요.

  • opcode(동작 코드) : 무슨 계산을 할지. MOVE, ADD, MUL, LOAD, STORE 등 (문장의 동사)
  • operand(피연산자) : 계산 대상. 숫자, 레지스터, 메모리 주소 (문장의 목적어)

이 수업의 가상 CPU에서는 16비트 명령 하나를 이렇게 4칸씩 끊어 읽어요. 아래 표가 기계어 빈칸 문제를 푸는 열쇠예요.

opcode2진수 (4비트)하는 일
MOVE1000값을 레지스터에 넣기 (대입)
LOAD1001메모리에서 레지스터로 읽기
STORE1010레지스터에서 메모리로 쓰기
ADD1100더하기
MUL1101곱하기

레지스터 번호는 그냥 2진수 4비트예요. R1=0001, R2=0010, R3=0011, R4=0100, R5=0101, R6=0110이에요. 아래 줄을 4칸씩 끊어서 읽어 보세요.

  • MOVE R1 2 = 1000 | 0001 | 0000 0010 → opcode(MOVE), 레지스터 R1, 숫자 2(8비트)
  • ADD R3 R1 R2 = 1100 | 0011 | 0001 | 0010 → opcode(ADD), 결과 R3, 더할 R1, 더할 R2
  • LOAD R5 CC = 1001 | 0101 | CC(8비트 주소)
  • STORE CC R3 = 1010 | CC(8비트 주소) | 0011

번지 CC와 CD는 16진수예요. 16진수 C는 10진수 12이고 2진수 1100이에요. D는 13이고 1101이에요. 그래서 CC = 1100 1100, CD = 1100 1101이에요. 이 값이 2023년 기출 정답과 교수님 설명이에요.

2023년 기출 Q6.1은 위 규칙으로 풀면 돼요.

④1100 1100LOAD R5 CC → 주소 CC

강의자료 12쪽 예시의 STORE·LOAD 줄에는 주소 자리에 1010 1010 같은 값이 적혀 있어서, 위 규칙(예 LOAD R5의 R5=0101)과 서로 맞지 않아요. 자료 그대로 외우지 말고 규칙으로 푸세요. 참고로 2023 시험지 그림의 4번째 줄 끝 4비트도 0101로 찍혀 있지만 빈칸 ①~⑥과는 상관없어요.

명령의 종류도 알아 둬요. 메모리 접근 명령은 LOAD(메모리에서 레지스터로 읽기)와 STORE(레지스터에서 메모리로 쓰기)예요. 레지스터 계산 명령은 MOVE, ADD, MUL처럼 레지스터끼리 계산해요. 이 둘 외에 분기·반복에서 PC 값을 바꾸는 프로그램 이동 명령도 있어요.

명령어 집합 구조(ISA, Instruction Set Architecture)는 "CPU가 알아듣고 계산할 수 있는 명령어 전체"예요. 이 목록은 CPU 제조사 설계에 따라 달라서, ISA가 다른 CPU에서는 같은 프로그램이 안 돌아가요. 인텔 펜티엄의 기계어는 명령마다 길이가 달라요(가변 길이). AVR은 길이가 같아요(고정 길이).

명령에 주소(operand)를 몇 개 적느냐에 따라 형식이 4가지예요.

형식예특징

1-주소ADD X

opcode는 "동사", operand는 "목적어"예요. 같은 동사는 같은 코드로 써요. 그러니 빈칸이 나오면 같은 opcode를 쓴 다른 줄을 먼저 찾아보세요(②, ⑤가 그 경우예요).

시험엔 이렇게 써요

기계어 명령어는 연산의 종류를 나타내는 동작 코드(opcode)와 연산의 대상을 나타내는 오퍼랜드(operand)로 구성된다. 명령어 집합 구조(ISA)는 CPU가 인식하여 계산할 수 있는 명령어들의 집합이며 CPU 제조사의 설계에 따라 달라진다. 어셈블리어는 기계어를 사람이 이해하기 쉽게 거의 1대1로 직역한 언어이다.

잠깐 확인 — ADD R3 R1 R2에서 opcode와 operand를 구분해 보세요.

opcode는 ADD(더하라)이고, operand는 R3, R1, R2예요. R1과 R2를 더해서 R3에 저장하라는 뜻이에요.

4-5. 명령 한 줄이 실행되는 5단계 ★★★ 시험 최다 출제

CPU는 명령 한 줄을 통째로 처리하지 않고, 더 작은 마이크로 명령 5개로 나눠서 실행해요. 이 5단계를 한 바퀴 도는 것을 주사이클(명령어 사이클)이라고 해요. 순서는 인출 → 해독 → 실행 → 데이터 → 기록이에요.

비유 — 도서관에서 책 빌려 계산하기

인출은 다음에 할 일이 적힌 쪽지를 가져오는 것, 해독은 쪽지 내용을 이해하는 것, 실행은 계산기를 두드리는 것이에요. 데이터는 책장(메모리)에서 책을 꺼내거나 꽂는 것, 기록은 결과를 내 노트(레지스터)에 적는 것이에요.

단계하는 일 (자료 기준)주로 쓰는 부품
1 인출
fetch		PC가 가리키는 번지의 명령을 메모리에서 읽어 IR로 가져와요. 그다음 PC는 다음 명령의 번지로 바뀌어요.PC, MAR, MBR, IR
2 해독
decode		CU가 IR의 명령을 해석하고 제어신호를 정해요. 계산에 쓸 값을 X, Y에 넣어요.CU, IR, X, Y
3 실행
execute		ALU가 계산해요. (레지스터 계산 명령일 때만)ALU, AC
4 데이터
data		MAR 번지에서 값을 MBR로 읽거나(읽기), MBR의 값을 MAR 번지에 써요(쓰기). (메모리 접근 명령일 때만)MAR, MBR, 메모리
5 기록

실제 예로 따라가 볼게요. 메모리 00번지에 MOVE R1 2, 02번지에 MOVE R2 3, 04번지에 ADD R3 R1 R2, 06번지에 STORE CC R3이 있어요. 명령 하나가 2칸(16비트 = 2바이트)을 차지해서 번지가 0, 2, 4, 6으로 2씩 늘어요. 그래서 PC도 2씩 늘어요. R1에는 2, R2에는 3이 이미 들어 있다고 해요.

예 1. 04번지 ADD R3 R1 R2 (레지스터 계산 명령) — 시험과 과제에 가장 많이 나온 예예요. PC=4에서 시작해요.

단계일어나는 일
1 인출PC 값 4를 MAR로 보내요 (MAR ← 4). 제어신호는 Read(읽기). 4번지의 명령이 MBR을 거쳐 IR로 들어가요 (MBR, IR ← ADD R3 R1 R2). PC는 6으로 바뀌어요 (PC: 4 ; PC ← 6).
2 해독CU가 IR을 해석해요. R1, R2의 값이 X ← 2, Y ← 3으로 들어가고 ALU 제어신호는 +예요.
3 실행ALU가 2 + 3을 계산해서 AC ← 5가 돼요.
4 데이터메모리를 안 쓰는 명령이라 No action이에요.
5 기록AC의 5를 R3에 기록해요 (R3 ← 5).

예 2. 06번지 STORE CC R3 (메모리 접근 명령) — 계산이 없어서 3단계가 No action이에요. PC=6에서 시작해요.

단계일어나는 일
1 인출MAR ← 6, 제어신호 Read, MBR와 IR ← STORE CC R3, PC ← 8.
2 해독IR 해석. 쓸 번지와 값을 준비해요 (MAR ← CC, MBR ← R3의 값 5).
3 실행No action (계산이 없어요).
4 데이터제어신호 Write. 메모리 CC번지에 MBR의 값을 써요 (MEM[CC] ← 5).
5 기록No action (레지스터에 쓸 것이 없어요).

예 3. LOAD R5 CC (스스로 해 보기) — 교수님이 "혼자 해 보라"고 한 명령이에요. 같은 방식으로 따라가면 해독에서 MAR ← CC, 데이터에서 Read로 MBR ← MEM[CC], 기록에서 R5 ← MBR이 돼요. 실행은 No action이에요.

왜 이렇게 쪼갤까요? 5단계는 서로 쓰는 부품이 달라서 신호가 겹치지 않아요. 덕분에 다음 절의 파이프라인처럼 겹쳐서 실행할 수 있어요.

2023년 기출 Q7은 이 그림을 그대로 냈어요. 04번지의 ADD를 실행하는 중이고, 메모리에는 00번지 MOVE R1 5, 02번지 MOVE R2 7이 들어 있었어요(그래서 R1=5, R2=7이에요). 답은 아래와 같아요.

빈칸답어떻게 알아보나
①인출(fetch)그림에 PC, MAR, IR, MBR 화살표가 있으면 인출이에요.
②, ③4, 6PC : 현재 값 ; PC ← 다음 값. 현재 04번지니까 4, 다음 명령은 06번지니까 6이에요.
④4MAR ← PC 값이에요.
⑤ADD R3 R1 R2IR ← 메모리에서 읽은 명령이에요.
⑥실행(execute)ALU, X, Y, 제어신호, AC가 보이면 실행이에요.
⑦+ADD니까 더하기 신호예요.

Q6.2도 같은 계산이에요. "1100 0011 0001 0010"(ADD R3 R1 R2)을 ALU에서 계산할 때 R1=2, R2=3이면 입력은 A=0000 0010, B=0000 0011, C=1000 0000, Y=0000 0101이에요. 제어신호 C는 왼쪽부터 +, -, ×, /, &, |, >>, << 순서(C7부터 C0)라서 더하기(+)는 맨 왼쪽 비트만 1이에요. 그래서 1000 0000이에요. Y는 2+3=5를 2진수로 쓴 0000 0101이에요.

외우기 팁

그림 문제는 어느 부품에 화살표가 있나로 단계를 알아봐요. PC·MAR·IR → 인출, X·Y·제어신호 → 해독(또는 실행), AC가 값을 받으면 실행, MAR·MBR에서 메모리로 → 데이터, 레지스터에 값이 들어가면 기록이에요. 계산(ADD, MUL)은 1-2-3-5, 메모리(LOAD, STORE)는 1-2-4-5예요.

시험엔 이렇게 써요

CPU는 하나의 기계어 명령을 인출(fetch), 해독(decode), 실행(execute), 데이터(data), 기록(write back)의 5단계 마이크로 명령으로 나누어 실행한다. 인출 단계에서는 PC의 주소를 MAR에 넣고 메모리에서 읽은 명령을 MBR을 거쳐 IR에 가져오며 PC는 다음 명령의 주소로 변경된다. 해독 단계에서는 제어장치가 IR의 명령을 해독하여 제어신호를 결정하고, 실행 단계에서는 ALU가 계산하여 결과를 AC에 둔다. 데이터 단계는 메모리 접근 명령에서만 MAR 주소와 MBR 사이에 값을 읽거나 쓰며, 기록 단계에서는 결과를 레지스터에 기록한다.

잠깐 확인 — ADD 명령에서 "데이터" 단계는 무슨 일을 하나요? 그리고 PC가 4일 때 인출 후 PC 값은?

ADD는 메모리를 안 쓰는 계산 명령이라 데이터 단계는 No action이에요. 명령이 2칸이라 인출 후 PC는 6이에요.

4-6. 파이프라인과 RISC·CISC ★

5단계는 서로 부품이 달라서 겹치지 않아요. 그러면 앞 명령이 해독 중일 때 다음 명령은 벌써 인출을 시작할 수 있겠죠. 이렇게 명령들이 한 칸씩 밀리며 동시에 진행하는 방식이 파이프라이닝(pipelining)이에요. 슬라이드에서 단계 이름은 FI(인출), DI(해독), EI(실행), BD(버퍼/데이터), WB(기록)로 적혀 있어요.

비유 — 세탁소 컨베이어

빨래를 한 벌씩 "씻기 → 말리기 → 다리기"를 끝내고 나서야 다음 벌을 시작하면 오래 걸려요. 첫 벌이 말리는 중일 때 둘째 벌을 씻으면 기계가 놀지 않아요. 파이프라인이 바로 이거예요.

손계산으로 비교해 봐요. 한 단계가 한 칸(한 클럭)이라고 하고 명령이 8개라면 이래요. (슬라이드 그림을 따라 센 계산이에요.)

  • 파이프라인 없이 순서대로: 8개 × 5칸 = 40칸
  • 파이프라인: 첫 명령이 끝나는 데 5칸, 이후 1칸마다 1개씩 끝나서 5 + 7 = 12칸

파이프라인을 잘 쓰려고 만든 설계 철학이 RISC예요. 요즘 CPU는 두 방식의 장점을 섞어 써요.

RISC (Reduced, 단순)CISC (Complex, 복잡)
철학단순한 명령을 여러 줄 써도 빨리빨리복잡해도 명령 한 줄로 처리
명령어종류가 적고 길이가 같아요(고정). 메모리는 LOAD/STORE로만 접근하고 계산은 레지스터끼리만 해요종류가 많고 길이가 달라요(가변)
예ARM 계열 (스마트폰, 애플 M칩)x86 계열 (인텔·AMD, PC·서버)

참고로 if문처럼 분기가 있으면 다음 명령이 어디인지 몰라 파이프라인이 끊겨요. 이를 줄이는 우회 경로(forwarding)가 슬라이드 46쪽에 나오지만, 교수님은 수업에서 자세히 다루지 않았어요.

시험엔 이렇게 써요

파이프라이닝은 여러 개의 명령이 인출-해독-실행-데이터-기록 단계를 한 칸씩 밀려서 동시에 진행하도록 하여 계산을 가속하는 기법이다. RISC는 단순한 명령어를 사용하고 메모리 접근을 적재/저장 명령으로 제한하여 파이프라인에 유리한 구조이고, CISC는 복잡한 명령을 사용하는 구조이다.

잠깐 확인 — 명령 10개를 5단계 파이프라인으로 처리하면 몇 칸이 걸리나요? (한 단계 = 한 칸)

5 + 9 = 14칸이에요. 순서대로 하면 10 × 5 = 50칸이에요.

4-7. CPU 성능 — 집적도, 클럭, 온도, 전력, 멀티코어 ★★

CPU의 성능 특성은 네 가지로 말해요. 자료 49쪽에 나오는 그대로예요.

요소무엇을 보나
집적도얼마나 많은 반도체(트랜지스터)가 들어 있나. 무어의 법칙 : 24개월(2년)마다 2배

무어의 법칙은 인텔 공동 창업자 고든 무어가 말한 "집적회로의 반도체 집적도가 2년마다 2배가 된다"는 경험 법칙이에요. 1970년대부터 2000년대 초반까지 잘 맞았어요. 메모리에 대한 비슷한 법칙을 황의 법칙이라고 해요.

손계산 요령: 2년에 2배라서 4년이면 2×2=4배, 6년이면 8배, 10년이면 25 = 32배예요. (년수 ÷ 2번 2를 곱해요.)

클럭은 CPU가 "딱, 딱" 하고 박자를 맞추는 횟수예요. 클럭이 높을수록 빠르지만, 전력 소모와 발열이 늘어서 CPU 온도가 올라가요. 온도가 너무 높으면(보통 100도 이하에서 동작) 회로가 상해요. 그래서 클럭을 무한정 높일 수 없어요. 3GHz CPU의 박자 한 번은 1 ÷ 30억 초 = 약 0.33나노초예요.

그래서 2000년대 초에 "클럭 전쟁"이 끝나고 멀티코어 시대로 넘어갔어요. 클럭을 올리는 대신 일꾼 수를 늘린 거예요.

용어뜻
싱글코어하나의 CPU 안에 연산 장치(코어)가 1개
멀티코어하나의 CPU 안에 연산 장치(코어)가 여러 개 (듀얼, 쿼드, 옥타...). 요즘은 싱글코어가 없어요
하이퍼스레딩파이프라인을 이용해 물리 코어 하나가 2배의 일을 병렬로 처리해서 코어를 가상으로 늘리는 기법

CPU 사양 읽기 예시예요. "1.8GHz, 4코어 8스레드"는 클럭 1.8GHz로 동작하고, 물리적인 연산 장치(코어)는 4개이며, 하이퍼스레딩으로 8개 코어가 하는 계산을 처리할 수 있다는 뜻이에요.

비유 — 주방 확장

요리사 한 명의 손을 더 빠르게 하는 데는 한계가 있어요(클럭). 그래서 요리사를 4명으로 늘렸어요(멀티코어). 하이퍼스레딩은 요리사 한 명이 가스레인지 두 곳을 번갈아 돌보며 2인분 일을 하는 거예요.

시험엔 이렇게 써요

무어의 법칙은 집적회로의 반도체 집적도가 24개월(2년)마다 2배씩 증가한다는 법칙이다. CPU 클럭이 높아질수록 전력 소모와 발열이 증가하여 CPU의 온도가 상승하며, 이는 클럭을 무한정 높일 수 없게 하는 주요 요인이다. 싱글코어는 하나의 CPU 안에 연산 장치가 1개인 것이고 멀티코어는 여러 개인 것이다.

잠깐 확인 — CPU 클럭을 계속 높이지 못하는 가장 큰 이유는?

클럭이 높을수록 전력 소모와 발열이 늘어 온도가 올라가기 때문이에요. 그래서 코어 수를 늘리는 멀티코어로 방향을 바꿨어요.

요즘 컴퓨터는 크롬, 파워포인트, 게임을 한꺼번에 켜 놔요. 이것을 가능하게 하는 용어가 여러 개라 헷갈려요. 7주차에 교수님이 정리한 것을 표로 모았어요.

멀티프로그래밍여러 프로그램을 동시에 RAM에 올려, 한 프로그램이 입출력으로 쉴 때 CPU가 다른 프로그램을 처리하게 해요―

빅데이터 처리에서 중요한 이유가 있어요. 40시간 걸리는 큰 작업을 10조각으로 나눠 동시에 돌리면(병렬 처리) 이론상 4시간이면 끝나요. 교수님은 파이썬은 멀티쓰레딩 병렬을 잘 지원하지 않아서 병렬 처리에 보통 멀티프로세싱을 쓴다고 했어요. 멀티태스킹과 멀티프로그래밍은 "안 써도 될 것 같다"고 했어요.

2023년 기출 Q1은 이 장의 용어 총정리예요. 답을 이렇게 외우세요.

번호답설명 문장 (기출)

1.2무어의 법칙집적도가 2년마다 2배

시험엔 이렇게 써요

멀티 프로세싱은 하나의 프로그램을 여러 개의 프로세스로 나누어 병렬 실행하는 것이고, 멀티 쓰레딩은 하나의 프로세스 안에서 여러 흐름(스레드)으로 병렬 실행하는 것이다. 멀티태스킹은 여러 프로그램이 동시에 실행되는 것처럼 보이게 하는 기술로, 싱글코어에서는 CPU 시간을 쪼개 번갈아 쓰는 시분할 방식으로 구현되었다.

잠깐 확인 — 크롬 창을 2개 띄운 것과 한 창에 탭을 2개 연 것 중 멀티프로세싱은 어느 쪽인가요?

창을 2개 띄운 쪽이에요(프로세스가 2개). 탭은 한 프로세스 안의 스레드라서 멀티쓰레딩이에요.

이 장 3줄 요약
  • CPU는 ALU(계산) + CU(제어) + 레지스터(PC, IR, AC, MAR, MBR 등)로 이루어지고, 프로그램은 보조기억장치 → RAM → CPU 순서로 한 줄씩 실행돼요.
  • 명령은 opcode + operand이고, 한 줄은 인출-해독-실행-데이터-기록 5단계로 실행돼요(계산은 1-2-3-5, 메모리는 1-2-4-5). 겹쳐 하면 파이프라인이에요.
  • 클럭을 높이면 발열(온도)이 늘어 한계가 있어서 멀티코어로 갔고, 병렬 처리는 멀티프로세싱(창)과 멀티쓰레딩(탭)으로 나뉘어요.
