데이터 표현 — 숫자와 글자를 0과 1로 바꾸는 법

컴퓨터는 전기 신호(0과 1)만 알아들어요. 그래서 우리가 쓰는 숫자와 글자는 모두 0과 1로 바꿔서 메모리에 넣어야 해요. 이 장에서는 진법 변환, 2의 거듭제곱, 문자 코드(ASCII)를 배워요. 2023 기출 4번이 "숫자 5개와 글자 5개를 1바이트 이진수로 바꿔 메모리에 쓰기"였어요.

2-1. 비트, 니블, 바이트 ★★

컴퓨터가 쓰는 가장 작은 단위가 비트(bit)예요. binary(2진) + digit(숫자)의 줄임말이고, 0 또는 1 딱 한 자리예요. 비트를 묶어서 부르는 이름이 따로 있어요.

이름크기설명
비트(bit)1자리0 또는 1
니블(nibble)4자리비트 4개 묶음. 16진수 1자리와 정확히 맞아요
바이트(byte)8자리비트 8개 묶음. 메모리의 기본 한 칸이에요
비유 — 숫자를 끊어 읽기

우리나라는 큰 숫자를 만 단위(네 자리)로 끊어서 읽고(1,0000,0000), 영어권은 세 자리(1,000,000)로 끊어요. 컴퓨터도 한 자리(비트), 네 자리(니블), 여덟 자리(바이트)로 끊어서 읽어요. 가장 많이 쓰는 단위가 바이트예요.

숫자에서 가장 큰 자리와 가장 작은 자리에는 이름이 있어요.

  • MSB(Most Significant Bit) : 이진수의 맨 왼쪽, 가장 큰 자리 비트예요.
  • LSB(Least Significant Bit) : 이진수의 맨 오른쪽, 가장 작은 자리 비트예요.
  • MSD, LSD : 같은 뜻인데 10진수일 때 쓰는 말(Digit)이에요. 12345678의 MSD는 1, LSD는 8이고, 00001111의 MSB는 0, LSB는 1이에요 (슬라이드 예제 2-1).

1바이트(8비트)로는 0 또는 1이 8자리이니 2를 8번 곱한 256가지(0~255)를 표현해요. 기출 4번의 "8 Bit(=1 Byte)가 1 word인 메모리"는 이 한 칸(1바이트)을 기본 단위로 쓰는 메모리라는 뜻이에요. 메모리는 칸마다 주소(01, 02 …)가 붙어 있어요.

숫자와 글자 말고 사진, 소리, 영상은 AD 변환(샘플링)으로 숫자로 바꾸는데, 이 수업에서는 생략했어요.

시험엔 이렇게 써요

비트(bit)는 2진수 한 자리(0 또는 1)이고, 4비트를 니블(nibble), 8비트를 바이트(byte)라고 한다. 이진수에서 가장 왼쪽의 최상위 비트를 MSB, 가장 오른쪽의 최하위 비트를 LSB라고 한다.

잠깐 확인 — (00001111)₂의 MSB와 LSB는 각각 무엇인가요?

MSB는 맨 왼쪽의 0, LSB는 맨 오른쪽의 1이에요.

2-2. 진법과 10진수 ↔ 2진수 변환 ★★★

교수님은 n진법의 규칙은 딱 두 개라고 했어요. 이 두 개만 알면 어떤 진법이든 쓸 수 있어요.

  • ① 쓰는 기호가 n개 : 10진법은 0~9의 10개, 2진법은 0과 1의 2개예요.
  • ② 자리값이 1, n, n², n³ … : 오른쪽부터 1의 자리, n의 자리, n²의 자리…예요.

숫자 53을 여러 진법으로 써 볼게요. 정말 같은 수인지 자리값으로 확인해요. 절대적인 수의 크기는 변하지 않고 표현만 달라져요.

진법쓴 모양풀어 보면
10진수535×10 + 3×1 = 53
2진수11010132 + 16 + 4 + 1 = 53
5진수2032×25 + 0×5 + 3×1 = 53
8진수656×8 + 5×1 = 53
16진수353×16 + 5×1 = 53

2진수 → 10진수는 쉬워요. 1이 있는 자리의 자리값을 더하면 돼요. 오른쪽부터 자리값은 1, 2, 4, 8, 16, 32, 64, 128이에요(2를 계속 곱한 수).

자리값1286432168421
0100110001001100

1이 있는 자리만 더해요. 64 + 8 + 4 = 76이에요. 같은 방법으로 10000011은 128 + 2 + 1 = 131이에요(슬라이드 예제 2-7).

10진수 → 2진수는 두 가지 방법이 있어요. 둘 다 같은 답이 나오니 편한 쪽을 고르세요.

방법 A — 큰 자리값부터 빼기 (손계산에 추천)

자리값 표(128 64 32 16 8 4 2 1)를 그려 놓고 왼쪽부터 "들어가면 1, 안 들어가면 0"을 쓰면서 남은 수를 줄여요. 137이면 128이 들어가니 1(남은 수 9), 64와 32와 16은 안 들어가니 0, 8이 들어가니 1(남은 수 1), 4와 2는 0, 1이 들어가니 1이에요. 답은 10001001이에요.

방법 B — 2로 계속 나누기

2로 나눈 나머지를 기록하고, 몫이 0이 될 때까지 반복해요. 마지막에 나머지를 아래에서 위로 읽어요. 몫이 묶음의 수이고, 나머지가 그 자리(1의 자리)의 숫자라는 뜻이에요(자료의 진법 변환 원리).

나누기몫나머지
137 ÷ 2681 (맨 아래 → 맨 오른쪽 자리)
68 ÷ 2340
34 ÷ 2170
17 ÷ 281
8 ÷ 240
4 ÷ 220
2 ÷ 210
1 ÷ 201 (맨 위가 가장 큰 자리)

나머지를 맨 아래에서 위로 읽으면 1, 0, 0, 0, 1, 0, 0, 1이라서 10001001이에요. 5진수나 8진수도 같은 방식이에요. 53을 5로 나누면 몫 10에 나머지 3, 10을 5로 나누면 몫 2에 나머지 0, 2를 5로 나누면 몫 0에 나머지 2라서 아래에서 위로 읽으면 203이에요.

파이썬은 이 변환을 대신 해 줘요. 직접 확인해 볼 수 있어요.

왜 컴퓨터가 2진법을 쓸까요? 사람끼리는 10진법으로 충분하지만, 반도체 회로는 5볼트(1)와 0볼트(0) 두 신호만 구별하기 때문이에요. 그래서 컴퓨터에 계산을 시키려면 모든 수가 2진수로 바뀌어야 해요.

시험엔 이렇게 써요

컴퓨터는 숫자를 2진수로 바꾸어 메모리에 저장한다. 10진수 137은 128 + 8 + 1이므로 8비트 이진수로 10001001이다. (변환 문제는 자리값 128 64 32 16 8 4 2 1 표를 먼저 그리고 한 칸씩 채우세요)

잠깐 확인 — 10진수 38을 8비트 이진수로 쓰면 무엇인가요?

00100110이에요. 38 = 32 + 4 + 2이니까 32, 4, 2 자리에 1을 써요.

2-3. 8진수와 16진수 — 묶어서 읽기 ★★★

2진수는 컴퓨터에는 좋지만 사람이 읽기엔 너무 길어요. 그래서 짧게 줄여 쓰려고 8진수와 16진수를 같이 써요. 요령은 한 줄이에요.

한 줄 정의

2진수를 오른쪽부터 3자리씩 묶으면 8진수(2³ = 8), 4자리씩 묶으면 16진수(2⁴ = 16).

16진수는 기호가 16개 필요해요. 0~9까지 쓰고 나서, 10 이상은 한 글자로 써야 해서 A(10), B(11), C(12), D(13), E(14), F(15)를 써요. 아래 대응표는 시험 전에 한 번 써 보세요.

시험엔 이렇게 써요

2진수를 8진수로 바꿀 때는 오른쪽부터 3비트씩(2³ = 8), 16진수로 바꿀 때는 4비트씩(2⁴ = 16) 묶어 각각 한 자리 수로 바꾼다. 16진수에서 10~15는 A~F로 표기한다.

잠깐 확인 — (10110110)₂를 16진수로 바꾸면 무엇인가요?

B6이에요. 1011 = 8+2+1 = 11 = B, 0110 = 4+2 = 6이에요.

2-4. 2의 거듭제곱과 데이터 크기 (KB, MB, GB, TB) ★★

메모리 용량은 항상 2의 거듭제곱으로 계산돼요. 숫자가 커서 겁나지만, 2¹⁰ = 1024 ≈ 1천만 알면 거의 다 풀려요.

2¹⁰1,0241K (킬로) ≈ 1천
2²⁰1,048,5761M (메가) ≈ 100만
2³⁰1,073,741,8241G (기가) ≈ 10억
2⁴⁰약 1.1조1T (테라) ≈ 1조
큰 거듭제곱 쉽게 계산하는 요령

지수를 10 + 나머지로 쪼개요. 2²⁷ = 2²⁰ × 2⁷ = 1M × 128 = 128M이에요. 2³⁴ = 2³⁰ × 2⁴ = 1G × 16 = 16G이고요. 즉 10단위는 K, M, G, T로 바꾸고 나머지 자리는 2의 작은 거듭제곱(1, 2, 4, 8, 16, 32, 64, 128, 256, 512)으로 써요.

비유 — 우체통 칸 수

메모리는 한 칸에 1바이트씩 들어가는 우체통이 줄지어 있다고 생각해 보세요. 16GB는 우체통이 약 171억 칸이에요. 칸마다 주소(번호)가 있어서 CPU가 번호로 찾아가요.

시험엔 이렇게 써요

2¹⁰ = 1,024 = 1K(킬로), 2²⁰ = 1M(메가), 2³⁰ = 1G(기가), 2⁴⁰ = 1T(테라)이다. 예를 들어 2²⁸ = 2²⁰ × 2⁸ = 256M이다.

잠깐 확인 — 2³²은 얼마인가요?

4G예요. 2³² = 2³⁰ × 2² = 1G × 4이고, 자릿수로 쓰면 4,294,967,296이에요.

2-5. 코드, 인코드·디코드, 고정길이 코드

숫자가 아닌 것(기호, 글자 등)도 2진수로 나타내야 해요. 이때 쓰는 약속이 코드예요.

한 줄 정의

코드 = 유한한 개수의 원소(기호)들을 서로 구별할 수 있게, 각 원소에 붙여 주는 숫자. 기호를 코드로 바꾸는 일이 인코드(encode), 코드를 보고 원래 기호를 찾는 일이 디코드(decode)예요.

비유 — 학번

학생 이름은 같은 사람이 있어도 학번은 모두 달라서 구별돼요. 학번을 붙이는 것이 인코드, 학번으로 학생을 찾는 것이 디코드예요.

코드는 길이에 따라 두 가지로 나뉘어요.

  • 고정길이 코드 : 모든 원소의 이진수 길이가 같아요.
  • 가변길이 코드 : 원소마다 이진수 길이가 달라요.

슬라이드 19쪽은 4개 기호 ♠ ◇ ♡ ♣에 코드 4가지를 붙여 놓고, ♣♡♠◇♡ 다섯 기호를 이어 쓴 뒤 다시 읽어 보게 해요.

그러면 원소가 N개일 때 고정길이 코드에는 몇 비트가 필요할까요? 비트 k개로는 2의 k제곱 가지를 표현하니까 (2의 k제곱) ≥ N인 가장 작은 k(= log₂N을 올림)예요.

원소 수 N필요한 최소 비트 수 (예제 2-9)
8개2³ = 8이므로 3비트
10개2³ = 8로는 부족하고 2⁴ = 16이면 충분해서 4비트
16개2⁴ = 16이므로 4비트
25개2⁴ = 16은 부족하고 2⁵ = 32면 충분해서 5비트
시험엔 이렇게 써요

코드는 유한개의 원소로 이루어진 집합의 각 원소를 구별할 수 있도록 부여한 숫자이며, 원소를 코드로 바꾸는 것을 인코드, 코드에서 원소를 찾는 것을 디코드라고 한다. 원소의 수가 N개일 때 고정길이 코드의 비트 수는 log₂N을 올림한 값이다.

잠깐 확인 — 원소 25개를 구별하는 고정길이 코드는 최소 몇 비트가 필요한가요?

5비트예요. 4비트로는 16가지, 5비트로는 32가지를 만들 수 있어서 25개를 구별하려면 5비트가 필요해요.

2-6. BCD — 십진수 한 자리씩 이진수로

잠깐 확인 — 10진수 7을 3초과 BCD로 쓰면 무엇인가요?

1010이에요. 7에 3을 더한 10을 4비트 이진수로 쓰면 1010이에요.

2-7. 문자 코드 — ASCII ★★★

컴퓨터에는 "글자"라는 것이 없어요. 0과 1뿐이에요. 그래서 "이 글자는 이 숫자"라고 미리 약속한 표가 필요한데, 영어와 숫자, 기호에 대한 가장 유명한 약속이 ASCII(아스키, American Standard Code for Information Interchange)예요.

ASCII 표는 아래처럼 생겼고, 시험에서도 표를 보여 줘요. 표 읽는 법은 이래요.

  • 가로(열)는 앞의 3비트(b6 b5 b4), 세로(행)는 뒤의 4비트(b3 b2 b1 b0)예요.
  • 글자를 찾아서 열의 3비트 + 행의 4비트를 이어 붙이면 7비트 코드가 나와요.
  • 메모리 한 칸은 8비트이니 맨 앞에 0을 하나 더 붙여서 1바이트로 저장해요.

대문자 R을 찾아볼게요. 표에서 R은 열 101, 행 0010에 있어요. 이어 붙이면 1010010이고 앞에 0을 붙여 01010010이에요. (10진수로는 82, 16진수로는 52예요.)

표 없이도 구하는 요령

알파벳은 차례대로 숫자가 1씩 커져요. 대문자는 A = 65, 소문자는 a = 97이에요(소문자가 32 커요). 숫자 글자 0은 48이고요.

R은 A에서 17번째 뒤이니 65 + 17 = 82예요. 82를 2진수로 바꾸면 01010010으로 같은 답이에요.

print(ord("R")) print(format(ord("R"), "08b")) print(chr(82))

print(format(ord("R"), "08b"))그 번호를 8자리 2진수(08b)로 써요
print(chr(82))chr는 번호를 글자로 되돌려요 (디코드)

실행 결과(출력)

잠깐 확인 — "Hello"는 메모리에서 몇 바이트를 차지하나요?

2-8. 패리티 비트와 유니코드

패리티 비트(parity bit)는 데이터가 올바른지 검사하려고 덧붙이는 비트 1개예요.

  • 짝수 패리티(even) : 전체에서 1의 개수가 짝수가 되도록 붙이는 비트예요.
  • 홀수 패리티(odd) : 전체에서 1의 개수가 홀수가 되도록 붙이는 비트예요.

예제 2-13의 A와 T를 풀어 볼게요. 먼저 ASCII의 7비트에서 1이 몇 개인지 세요.

글자ASCII 7비트1의 개수짝수 패리티 비트홀수 패리티 비트
A10000012개 (짝수)0 (이미 짝수)1 (홀수로 만듦)
T10101003개 (홀수)1 (짝수로 만듦)0 (이미 홀수)

왜 붙일까요? 데이터를 주고받다가 비트 하나가 바뀌면 1의 개수의 짝홀이 규칙과 달라져서 오류를 알아챌 수 있기 때문이에요.

ASCII는 영어에 최적화돼 있어서 한글은 못 담아요. 그래서 전 세계 글자를 담는 유니코드(Unicode)가 만들어졌어요.

  • 국제적으로 통용되는 16비트 문자 체계예요. 1991년에 1.0 버전이 나왔어요.
  • U+0000 ~ U+007F 영역은 영문자(ASCII와 같은 칸)이고, 그 뒤로 여러 나라 글자가 이어져요.
  • 한글은 U+AC00부터 U+D7A3까지 11,172자예요. 자음·모음만이 아니라 조합된 글자 하나하나가 모두 자기 번호를 가져요.
print(hex(ord("홍"))) print(ord("홍")) print(chr(0xD64D))
코드 줄무슨 뜻인가요
print(hex(ord("홍")))"홍"의 유니코드 번호를 16진수로 보여 줘요
print(ord("홍"))같은 번호를 10진수로 보여 줘요
print(chr(0xD64D))16진수 D64D 번호의 글자를 찾아요

실행 결과(출력)

0xd64d 54861 홍

그래서 예제 2-14 "홍길동"의 유니코드는 홍 = U+D64D, 길 = U+AE38, 동 = U+B3D9예요.

교수님이 덧붙인 주의점이 있어요. 한글은 저장 방식(인코딩)이 여러 개예요. UTF-16은 한글 한 글자가 2바이트이고 UTF-8은 3바이트예요.

쓸 때와 읽을 때의 방식이 다르면 글자가 깨져요. 그래서 변수 이름과 코드는 영어로 쓰라고 권했어요.

시험엔 이렇게 써요

패리티 비트는 데이터가 올바른지 검사하기 위해 추가하는 비트로, 짝수 패리티는 1의 개수가 짝수가 되도록, 홀수 패리티는 홀수가 되도록 붙인다. 유니코드는 세계 각국의 언어를 표현하는 국제 문자 체계이며 한글은 U+AC00부터 U+D7A3까지 11,172자가 정의되어 있다.

잠깐 확인 — 7비트 1010100(T)에 짝수 패리티 비트를 붙이면 몇이 되나요?

1이에요. 1이 3개(홀수)라서 하나를 더 붙여야 총 4개(짝수)가 돼요.

2-9. 기출 4번 — 메모리 칸에 숫자와 글자 쓰기 ★★★

2023 기출 4번은 이 장의 내용을 한 번에 묻는 문제예요. 한 칸이 8비트(1바이트)인 메모리에 다섯 개 숫자 137, 7, 38, 77, 11과 글자 R, o, b, o, t를 01~10번 주소에 순서대로 쓰는 거예요. 푸는 순서는 두 단계예요.

  • 글자 : ASCII 표에서 코드를 찾아 맨 앞에 0을 붙인 8비트로 써요 (2-7).

잠깐 확인 — 77을 8비트 이진수로 쓰면 무엇인가요?

01001101이에요. 77 = 64 + 8 + 4 + 1이라서 64, 8, 4, 1 자리에 1을 써요.

2-10. 참고 — 음수와 실수는 어떻게 표현할까요

이 소단원은 강의자료와 수업에 나오지 않은 참고 내용이에요. 시험에 나올 가능성은 낮으니, 궁금하거나 시간이 남을 때 읽어 보세요.

음수 표현이에요. 비트에는 "-" 기호가 없어서 맨 왼쪽 비트(MSB)를 부호 자리로 약속하거나(0은 양수, 1은 음수), 보수를 써요. 8비트에서 5와 -5를 나타내 볼게요.

방법만드는 법-5 (8비트)특징
부호-크기맨 왼쪽만 1로 바꾸고 나머지는 크기 그대로10000101이해하기 쉽지만 0이 두 개(00000000, 10000000)예요
1의 보수5(00000101)의 모든 비트를 뒤집기111110100이 두 개(00000000, 11111111)예요
2의 보수1의 보수에 1을 더하기111110110이 하나뿐이고, 덧셈 회로 그대로 뺄셈이 돼요

컴퓨터는 거의 2의 보수를 써요. 8비트로 -128부터 +127까지를 나타내요. 5 + (-5)가 정말 0이 되는지 해 볼게요.

00000101 + 11111011 = 1 00000000이에요. 9번째 올림(맨 앞의 1)은 버리면 00000000, 즉 0이에요. 덧셈기 하나로 뺄셈까지 되는 이유가 이거예요(3장의 덧셈기).

실수 표현(소수점이 있는 수)이에요. 컴퓨터는 소수를 과학적 표기법처럼 써요. 12345.6을 1.23456 × 10⁴로 쓰는 식으로, 소수점이 "떠다닌다"고 해서 부동소수점(floating point)이라고 해요.

2진수로는 부호 + 지수 + 가수 세 덩어리로 나눠요. 대표 규격은 32비트(부호 1, 지수 8, 가수 23)와 64비트(부호 1, 지수 11, 가수 52)예요.

한 가지 재미있는 사실이에요. 10진수 1/3이 0.333…으로 끝없이 이어지듯, 0.1은 2진수로 끝없이 이어져서 정확히 담을 수 없어요.

print(0.1 + 0.2) print(0.1 + 0.2 == 0.3)
코드 줄무슨 뜻인가요
print(0.1 + 0.2)0.1과 0.2를 더한 값을 보여 줘요
print(0.1 + 0.2 == 0.3)그 값이 0.3과 같은지 비교해요 (==는 "같은가"를 묻는 기호)

실행 결과(출력)

0.30000000000000004 False

작은 오차가 생기는 것은 컴퓨터가 고장 난 것이 아니라 이진수 표현의 한계예요.

시험엔 이렇게 써요

(참고 문장) 음수는 2의 보수(모든 비트를 뒤집고 1을 더함)로 표현하면 덧셈기로 뺄셈을 할 수 있다. 소수는 부호, 지수, 가수로 나누어 저장하는 부동소수점 방식으로 표현한다.

잠깐 확인 — 8비트에서 -5의 2의 보수 표현은 무엇인가요?

11111011이에요. 5(00000101)를 뒤집어 11111010을 만들고 1을 더해요.

이 장 3줄 요약
  • 비트(0 또는 1) 4개가 니블, 8개가 바이트이고, 숫자는 자리값(128 64 32 16 8 4 2 1)으로 2진수로 바꾸며, 2진수를 오른쪽부터 3자리씩 묶으면 8진수, 4자리씩 묶으면 16진수예요.
  • 2¹⁰ = 1K, 2²⁰ = 1M, 2³⁰ = 1G, 2⁴⁰ = 1T이고 큰 거듭제곱은 "10단위 + 나머지"로 쪼개 계산해요. 원소 N개의 고정길이 코드는 log₂N 올림 비트가 필요해요.
  • 글자는 ASCII 표(열 3비트 + 행 4비트, 앞에 0)로 1바이트 코드가 되고(R = 01010010), 오류 검사는 패리티 비트, 한글 등은 유니코드(한글 U+AC00~U+D7A3)로 표현해요.
