A. 컴퓨터 큰 그림 (Q1·Q2·Q3, 32점)

1. 폰노이만 구조

계산장치(CPU)와 기억장치로 구성되어, 계산장치가 기억장치의 프로그램을 한 줄씩 실행하고 결과를 기억장치에 기록하는 구조이다.

쉽게 요리사(CPU)가 냉장고(기억장치)에서 레시피를 한 줄 꺼내 요리하고, 결과를 다시 냉장고에 넣어요. 지금 쓰는 컴퓨터는 전부 이 방식이에요.

외우기 "꺼내서 → 한 줄 실행 → 다시 기록". 빈칸에 "폰노이만 구조"가 답이에요.

2. 무어의 법칙

집적회로의 반도체 집적도가 2년(24개월)마다 2배씩 증가한다는 법칙이다.

쉽게 손톱만 한 칩에 들어가는 부품 수가 2년마다 두 배가 된다는 얘기예요. 그래서 컴퓨터가 계속 빨라졌어요.

외우기 "무어 = 2년에 2배" (무-이-이). 보기의 "황의 법칙"은 함정이에요.

3. 싱글코어 · 멀티코어 · 온도

싱글코어는 CPU 안에 연산 장치가 1개, 멀티코어는 여러 개이다. 클럭이 높을수록 전력·발열이 늘어 온도가 올라가므로 클럭을 무한정 높일 수 없다.

쉽게 코어는 CPU 안의 일꾼이에요. 일꾼 1명이면 싱글, 여럿이면 멀티. 일꾼을 더 빨리 뛰게(클럭↑) 하면 땀(열)이 나서 한계가 있어요.

외우기 "클럭 한계의 이유 = 온도". 빈칸 1.5는 "온도"예요.

4. 프로그램 vs 프로세스

코드가 보조기억장치에 보관되어 있으면 프로그램, 실행되어 메모리에 적재되어 있으면 프로세스이다.

쉽게 책장에 꽂힌 레시피 책 = 프로그램, 펴서 지금 요리 중인 레시피 = 프로세스.

외우기 "저장돼 있으면 프로그램, 돌아가면 프로세스" (프로그램은 가만히, 프로세스는 진행 중).

5. 멀티 프로세싱 vs 멀티 쓰레딩

하나의 프로그램을 여러 프로세스로 병렬 실행하면 멀티 프로세싱, 하나의 프로세스 안에서 여러 흐름으로 병렬 실행하면 멀티 쓰레딩이다.

쉽게 크롬 창을 여러 개 띄우면 멀티 프로세싱, 창 하나 안에 탭이 여러 개면 멀티 쓰레딩.

외우기 "창 = 프로세스, 탭 = 쓰레드".

6. 운영체제

컴퓨터 전원이 켜지면 가장 먼저 시작되어, 컴퓨터 자원을 관리하고 여러 응용 프로그램의 실행을 관리하는 프로그램이다.

쉽게 윈도우 같은 것이에요. 학교의 교무실처럼 누가 언제 교실(CPU·메모리)을 쓸지 정해 줘요.

외우기 "제일 먼저 켜지는 관리자" = 운영체제.

7. 6대 부품 (Q2, 12점)

메인보드는 데이터가 전송되는 통로, CPU는 대부분의 계산, 보조기억장치(SSD/HDD)는 비휘발성 반영구 보관, RAM은 휘발성으로 실행 중인 코드·데이터 보관, GPU는 그래픽·병렬 계산, 전원공급장치는 전기를 공급한다.

쉽게 몸에 비유하면 메인보드 = 혈관(길), CPU = 뇌, RAM = 책상(지금 펼친 것), SSD = 책장(오래 보관), GPU = 그림 잘 그리는 손, 전원 = 심장.

외우기 기출 번호 "1 보조기억 · 2 GPU · 3 전원 · 4 CPU · 5 RAM · 6 메인보드". 설명 a 통로=6, b 계산=4, c 비휘발=1, d 휘발=5.

8. 휘발성 · sum.py 실행 과정 (Q3)

휘발성은 전원이 꺼지면 데이터가 사라지는 성질이다. sum.py는 보조기억장치(SSD)에 있다가 실행되면 RAM에 적재되고, CPU가 한 줄씩 계산하며 결과(변수 값)는 다시 RAM에 기록된다.

쉽게 책장(SSD)에서 책을 꺼내 책상(RAM)에 펴고, 뇌(CPU)가 한 줄씩 읽어 계산한 답을 책상 메모지(RAM)에 적어요. 전원을 끄면 책상 위는 싹 치워져요(휘발).

외우기 "SSD → RAM → CPU → RAM" (책장 → 책상 → 뇌 → 책상).

B. 회로 (Q5, 10점)

9. 논리 게이트

AND는 모두 1일 때만 1, OR는 하나라도 1이면 1, NOT은 반대, XOR는 같으면 0 다르면 1이다. 입력 00·01·10·11에 대해 AND 0001, OR 0111, XOR 0110이다.

쉽게 AND = 엄마 아빠 둘 다 허락해야 외출, OR = 한 명만 허락해도 외출, XOR = 둘 의견이 다를 때만 1.

외우기 진리표 맨 아랫줄(11)만 기억 — AND 1, OR 1, XOR 0. 나머지는 "AND는 1이 하나, OR는 0이 하나, XOR는 가운데 둘".

10. 반가산기 · 전가산기 · 8비트 덧셈기

반가산기는 두 비트를 더해 합 S(XOR)와 올림 Cout(AND)을 내고, 전가산기는 아랫자리 올림 Cin까지 세 비트를 더한다. 8비트 덧셈기는 전가산기 8개를 이어 i번의 Cout을 i+1번의 Cin에 연결하고 맨 아래 Cin은 0이다.

쉽게 손으로 덧셈할 때 "받아올림"을 옆 칸에 넘기잖아요. 전가산기 8개가 한 줄로 서서 받아올림(Cout)을 왼쪽 친구의 Cin으로 넘겨요. 맨 오른쪽은 넘겨받을 게 없으니 0.

외우기 "합은 XOR, 올림은 AND" · "반은 둘, 전은 셋(전가산기는 Cin까지 3개)".

C. CPU (Q6·Q7, 20점 — 교수님 강조)

11. CPU 구성 요소

CPU는 ALU(산술·논리 계산), 제어장치 CU(명령 해독과 제어 신호), 레지스터 세트(CPU 안의 작고 빠른 메모리)로 구성된다.

쉽게 ALU = 계산기, 제어장치 = 지휘자, 레지스터 = 손바닥 메모지(제일 빠른 저장).

외우기 "계산기 · 지휘자 · 메모지" = ALU · CU · 레지스터.

12. 레지스터 이름

PC는 다음 명령의 주소, IR은 현재 명령, MAR은 접근할 메모리 주소, MBR은 메모리에서 읽거나 쓸 값, AC는 계산 결과를 저장한다.

쉽게 PC = 책갈피(다음에 읽을 쪽), IR = 지금 읽는 문장, MAR = 찾아갈 사물함 번호, MBR = 사물함에서 꺼낸 물건, AC = 계산기 화면.

외우기 글자 뜻으로 — Program Counter(다음 줄 세기), Instruction(명령), Memory Address(주소), Memory Buffer(값), ACcumulator(결과).

13. 기계어 = opcode + operand (Q6)

기계어 명령은 연산 종류인 opcode와 연산 대상인 operand로 구성된다. ADD R3 R1 R2에서 ADD가 opcode, R3·R1·R2가 operand이다.

쉽게 "더해라(opcode) / 무엇을(operand)". "R1과 R2를 더해서 R3에 넣어라"라는 문장이에요.

외우기 "op = 동사, operand = 목적어".

14. 명령 실행 5단계 (Q7) ★

명령 한 줄은 인출(fetch) → 해독(decode) → 실행(execute) → 데이터(data) → 기록(write back)의 5단계로 실행된다.

쉽게 도서관 비유 — 쪽지 가져오기(인출) → 무슨 뜻인지 읽기(해독) → 계산기 두드리기(실행) → 책장에서 책 꺼내거나 꽂기(데이터) → 노트에 적기(기록).

외우기 "인해실데기" (인-해-실-데-기, "인해 실데기"로 소리 내기).

15. 어떤 단계를 건너뛰나

ADD 같은 계산 명령은 데이터 단계가 No action(1-2-3-5)이고, LOAD·STORE 같은 메모리 접근 명령은 실행 단계가 No action(1-2-4-5)이다.

쉽게 계산만 하는 명령은 책장(메모리)에 갈 일이 없고, 책장에서 꺼내기만 하는 명령은 계산기를 안 써요.

외우기 "계산은 4번 쉼, 메모리는 3번 쉼" (ADD 1235, LOAD 1245).

16. 인출 단계 안에서 일어나는 일

인출 단계에서는 PC의 주소를 MAR에 넣고, 메모리에서 읽은 명령을 MBR을 거쳐 IR로 가져오며, PC는 다음 명령 주소로 바뀐다. PC가 4이고 명령이 2칸이면 MAR은 4, PC는 6이 된다.

쉽게 책갈피(PC) 쪽수를 사물함 번호(MAR)에 적고 → 꺼낸 쪽지(MBR)를 지금 읽는 칸(IR)에 놓고 → 책갈피를 다음 쪽으로 옮겨요.

외우기 "PC → MAR → MBR → IR, 그리고 PC 증가" (피-마-엠-아이).

D. 메모리 (Q8·Q9, 19점)

17. 메모리 계층

메모리 계층은 레지스터 → 캐시 → RAM → 보조기억장치(SSD/HDD) 순으로 빠르며, 위로 갈수록 용량이 작고 비싸다. CPU 안에 있는 메모리는 레지스터와 캐시이다.

쉽게 손바닥(레지스터) → 책상 서랍(캐시) → 책상 위(RAM) → 책장(SSD) → 창고(HDD). 가까울수록 빠르지만 좁아요.

외우기 "레캐램보" — 위로 갈수록 빠르고 작고 비싸다(빠작비).

18. SRAM · DRAM · 캐시 히트

SRAM은 빠르고 비싸서 캐시에, DRAM은 싸고 집적도가 높아 RAM(주기억장치)에 쓴다. 필요한 데이터가 캐시에 있으면 히트, 없으면 미스이다.

쉽게 서랍(캐시)을 열었는데 찾는 게 있으면 히트(성공), 없어서 책상까지 가야 하면 미스(실패).

외우기 "S = Speed(캐시), D = 싸고 많이(RAM)".

19. 레이턴시 vs 대역폭 ★ 교수님 강조

레이턴시는 데이터에 접근하는 데 걸리는 시간(낮을수록 좋음)이고, 대역폭은 단위 시간당 전송할 수 있는 데이터의 양(높을수록 좋음)이다. 둘은 서로 다른 개념이다.

쉽게 택배로 치면 레이턴시 = 첫 상자가 도착하기까지 걸린 시간, 대역폭 = 트럭 한 대에 실을 수 있는 상자 수. 빨리 오는 오토바이(레이턴시↓)와 많이 싣는 트럭(대역폭↑)은 다른 얘기예요.

외우기 "레이턴시 = 기다림(시간), 대역폭 = 도로 폭(양)".

20. 가상메모리 · 페이지 · 프레임

가상메모리는 실제 메모리 크기와 관계없이 프로세스에 큰 메모리 공간을 주는 기술이다. 가상메모리는 페이지, 물리메모리는 같은 크기의 프레임으로 나누며, 주소 변환은 페이지 번호만 프레임 번호로 바꾸고 오프셋은 그대로 둔다.

쉽게 아파트 동·호수 바꾸기예요. "가상 3동 05호"를 "실제 7동 05호"로 — 동(페이지→프레임)만 바뀌고 호수(오프셋)는 그대로.

외우기 "가상은 페이지, 진짜는 프레임, 오프셋은 그대로".

21. 스와핑 · 40GB 문제 (Q9)

프로세스가 쓰는 메모리가 물리메모리(RAM)보다 크면 일부가 보조기억장치의 스왑 영역으로 이동하는데, 이것이 스와핑이며 컴퓨터가 느려진다. 코드를 고치지 않고 해결하려면 RAM을 늘린다.

쉽게 책상(RAM)이 좁아서 책 일부를 바닥 창고(SSD 스왑)에 내려놨다가 필요할 때마다 다시 올리니 느려져요. 해결은 책상을 키우기(RAM 증설).

외우기 "RAM 넘치면 스왑 → 느림 → RAM 늘리기".

22. 주소 변환 순서 ★ 교수님 "빈칸 낼 테니 암기"

주소 변환은 TLB → 페이지 테이블 → (필요하면 스왑 영역) → 캐시 순으로 진행된다. TLB 히트면 물리주소를 바로 얻고, 미스면 페이지 테이블을 찾는다.

쉽게 TLB = 자주 가는 집 주소를 적은 포스트잇, 페이지 테이블 = 전체 주소록. 포스트잇에 있으면 바로, 없으면 주소록을 펼쳐요.

외우기 "포스트잇 → 주소록 → 창고 → 서랍" = TLB → 페이지 테이블 → 스왑 → 캐시.

23. 페이지 폴트

필요한 페이지가 RAM에 없으면 페이지 폴트가 발생하고, 운영체제가 스왑 영역의 페이지를 RAM에 올린 뒤 페이지 테이블과 TLB를 갱신한다. TLB 미스가 곧 페이지 폴트인 것은 아니다.

쉽게 주소록엔 있는데 그 책이 책상이 아니라 창고에 있는 상황이에요. 관리자(운영체제)가 창고에서 가져와 책상에 놓고 주소록을 고쳐요.

외우기 "포스트잇에 없음 = TLB 미스(아직 괜찮음), 책상에 없음 = 페이지 폴트(창고 다녀옴)".

E. 보조기억장치 (Q10, 9점)

24. 저장 원리

HDD는 자기적, CD-ROM은 광학적, SSD는 전자적 성질을 이용해 데이터를 저장한다.

쉽게 HDD = 자석 원판, CD = 빛(레이저), SSD = 전기(반도체 칩).

외우기 "하자 · 씨광 · 에스전" (HDD 자기, CD 광학, SSD 전자).

25. SSD vs HDD · RAID · 파티션

SSD는 HDD보다 빠르지만 같은 용량에 비싸므로 운영체제는 SSD에, 동영상·사진은 HDD에 둔다. 여러 디스크를 하나처럼 묶는 것이 RAID, 디스크 하나를 나눠 쓰는 것이 파티션이다.

쉽게 자주 꺼내는 건 빠른 SSD, 크고 덜 쓰는 사진은 싼 HDD. 여러 개를 묶으면 RAID, 하나를 나누면 파티션.

외우기 "묶으면 RAID, 나누면 파티션".

순서 3개는 통째로

1. CPU 명령 5단계 (Q7, 교수님 지시)

인출 → 해독 → 실행 → 데이터 → 기록

외우기 요령은 앞글자 인해실데기입니다. 계산 명령은 데이터를 건너뛰고(1-2-3-5), 메모리 명령은 실행을 건너뜁니다(1-2-4-5).

2. 주소 변환 과정 (빈칸으로 나온다고 교수님이 말함)

TLB → 페이지 테이블 → (페이지 폴트면 스왑에서 RAM으로) → 캐시 → (미스면) 메모리

외우기 요령은 티-페-스-캐입니다. TLB에 없으면 페이지 테이블, RAM에 없으면 스왑, 물리주소를 얻은 뒤에 캐시입니다.

3. 프로그램 실행 과정 (Q3)

보조기억장치(SSD) → 주기억장치(RAM) 적재 → CPU가 한 줄씩 계산 → 결과를 RAM에 기록

외우기 요령은 보 → 주 → C → 기입니다. 빈칸 A는 보조기억장치, B는 주기억장치, C는 CPU입니다.

계산은 이 요령만

1. 십진수 → 8비트 이진수 (Q4)

여백에 자릿값 128 64 32 16 8 4 2 1을 먼저 쓰고, 큰 것부터 들어가면 1 아니면 0을 쓴 뒤 남은 수로 다음 자리를 봅니다. 마지막에 더해서 검산합니다. 문자는 ASCII 표에서 번호(A=65, a=97)를 찾아 같은 방법으로 바꿉니다.

예

137 = 128 + 8 + 1이라 1000 1001입니다. 77 = 64 + 8 + 4 + 1이라 0100 1101입니다.

2. 전가산기로 덧셈 (Q5)

오른쪽 자리부터 한 자리씩 A, B, 올림 Cin 세 개에서 1의 개수를 셉니다. 1이 1개면 S=1에 올림 0, 2개면 S=0에 올림 1, 3개면 S=1에 올림 1입니다. 올림은 왼쪽 자리로 넘기고 맨 아래 Cin은 0입니다.

예

0000 0111 + 0000 0101은 0번 자리 S=0 올림 1, 1번 자리 S=0 올림 1, 2번 자리 S=1 올림 1, 3번 자리 S=1이라 0000 1100(= 12)입니다.

3. ALU 입력값 A, B, C, Y (Q6)

레지스터에 든 값을 그림에서 찾아 8비트 이진수로 A, B에 씁니다. 제어신호 C는 + − x / & | >> << 순서에서 해당 연산 자리만 1입니다(덧셈 1000 0000). Y는 계산 결과를 이진수로 씁니다.

예

ADD R3 R1 R2에서 R1=2, R2=3이면 A=0000 0010, B=0000 0011, C=1000 0000, Y=0000 0101(= 5)입니다.
