Q9. 40GB 파일을 읽었더니 컴퓨터가 멈췄어요 (8점)

열이 1000개, 줄이 400만 개인 40GB짜리 bigdata.csv를 HDD에 저장했어요. 컴퓨터 사양은 8코어 CPU, 16GB RAM, 1TB HDD예요. 다음 코드를 돌렸더니 컴퓨터가 렉이 걸려 거의 멈췄어요.

import pandas x = pandas.read_csv("bigdata.csv") print( x['x1'].mean() )
코드 줄무슨 뜻
import pandas표 데이터를 다루는 도구(pandas)를 불러와요.
x = pandas.read_csv("bigdata.csv")csv 파일 전체를 읽어서 x라는 표로 만들어요. 파일 40GB가 통째로 메모리에 올라와요.
print( x['x1'].mean() )x1 열의 평균을 구해서 화면에 출력해요.

실행 결과 RAM이 충분하면 x1 열의 평균값 숫자 하나가 출력돼요. 여기서는 RAM이 16GB뿐이라 출력 전에 컴퓨터가 느려져요.

9.1 정답 (각 1점)

칸정답
A가상메모리
B물리메모리
C보조기억장치
D스왑메모리
E스와핑

왜 그런지 프로세스는 자기만의 큰 가상메모리(A) 공간이 있는 것처럼 데이터를 올려요. 운영체제가 이것을 실제 RAM인 물리메모리(B)에 할당하려 하는데, 40GB가 16GB보다 커서 넘치는 부분은 보조기억장치(C)의 스왑메모리(D) 영역으로 쫓겨나요. RAM 용량을 넘어 스왑을 쓰는 이 과정이 스와핑(E)이에요. HDD는 RAM보다 수만 배 이상 느려서(RAM 50~70ns, HDD 5~20ms) 컴퓨터 전체가 거의 멈춰요.

9.2 정답 (3점) 코드를 고치지 않고 부품만 올린다면 RAM을 40GB보다 넉넉하게(예 64GB 이상) 늘려야 해요. 40GB 파일을 읽고 처리할 충분한 RAM 용량을 확보하면 스왑이 필요 없어져요.

왜 CPU나 HDD가 아닌가요. CPU는 8코어라 계산 능력이 문제가 아니고, HDD는 1TB라 40GB가 들어가고도 남아요. 병목은 "RAM이 데이터보다 작다"예요.

참고 (시험 범위 밖)

실무에서는 코드를 고쳐 필요한 열(x1)만 읽거나 조금씩 나눠 읽는 방법도 써요. 이번 문제는 "코드를 수정하지 않고 부품을 업그레이드"가 조건이라 RAM이 답이에요.

올해 시험에서도 이렇게 쓰세요

"데이터가 RAM(물리메모리) 용량을 초과하면 일부가 보조기억장치의 스왑 영역으로 옮겨지는 스와핑이 일어나고, 접근 속도가 느린 보조기억장치를 계속 써서 컴퓨터가 느려진다. 따라서 데이터 크기보다 큰 RAM(40GB 이상)으로 업그레이드해야 한다"로 쓰세요. 7주차 가상메모리 수업의 핵심 문장이에요.

잠깐 확인 — RAM이 모자라 데이터가 보조기억장치로 밀려나는 것을 뭐라고 하나요?

스와핑이에요. 밀려난 영역을 스왑메모리(스왑 영역)라고 불러요.
