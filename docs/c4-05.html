명령 한 줄이 실행되는 5단계 ★★★ 시험 최다 출제

CPU는 명령 한 줄을 통째로 처리하지 않고, 더 작은 마이크로 명령 5개로 나눠서 실행해요. 이 5단계를 한 바퀴 도는 것을 주사이클(명령어 사이클)이라고 해요. 순서는 인출 → 해독 → 실행 → 데이터 → 기록이에요.

비유 — 도서관에서 책 빌려 계산하기

인출은 다음에 할 일이 적힌 쪽지를 가져오는 것, 해독은 쪽지 내용을 이해하는 것, 실행은 계산기를 두드리는 것이에요. 데이터는 책장(메모리)에서 책을 꺼내거나 꽂는 것, 기록은 결과를 내 노트(레지스터)에 적는 것이에요.

단계하는 일 (자료 기준)주로 쓰는 부품
1 인출
fetch		PC가 가리키는 번지의 명령을 메모리에서 읽어 IR로 가져와요. 그다음 PC는 다음 명령의 번지로 바뀌어요.PC, MAR, MBR, IR
2 해독
decode		CU가 IR의 명령을 해석하고 제어신호를 정해요. 계산에 쓸 값을 X, Y에 넣어요.CU, IR, X, Y
3 실행
execute		ALU가 계산해요. (레지스터 계산 명령일 때만)ALU, AC
4 데이터
data		MAR 번지에서 값을 MBR로 읽거나(읽기), MBR의 값을 MAR 번지에 써요(쓰기). (메모리 접근 명령일 때만)MAR, MBR, 메모리
5 기록
write back		계산 결과 또는 메모리에서 읽은 값을 레지스터에 기록해요.AC 또는 MBR, 레지스터

실제 예로 따라가 볼게요. 메모리 00번지에 MOVE R1 2, 02번지에 MOVE R2 3, 04번지에 ADD R3 R1 R2, 06번지에 STORE CC R3이 있어요. 명령 하나가 2칸(16비트 = 2바이트)을 차지해서 번지가 0, 2, 4, 6으로 2씩 늘어요. 그래서 PC도 2씩 늘어요. R1에는 2, R2에는 3이 이미 들어 있다고 해요.

예 1. 04번지 ADD R3 R1 R2 (레지스터 계산 명령) — 시험과 과제에 가장 많이 나온 예예요. PC=4에서 시작해요.

단계일어나는 일
1 인출PC 값 4를 MAR로 보내요 (MAR ← 4). 제어신호는 Read(읽기). 4번지의 명령이 MBR을 거쳐 IR로 들어가요 (MBR, IR ← ADD R3 R1 R2). PC는 6으로 바뀌어요 (PC: 4 ; PC ← 6).
2 해독CU가 IR을 해석해요. R1, R2의 값이 X ← 2, Y ← 3으로 들어가고 ALU 제어신호는 +예요.
3 실행ALU가 2 + 3을 계산해서 AC ← 5가 돼요.
4 데이터메모리를 안 쓰는 명령이라 No action이에요.
5 기록AC의 5를 R3에 기록해요 (R3 ← 5).

예 2. 06번지 STORE CC R3 (메모리 접근 명령) — 계산이 없어서 3단계가 No action이에요. PC=6에서 시작해요.

단계일어나는 일
1 인출MAR ← 6, 제어신호 Read, MBR와 IR ← STORE CC R3, PC ← 8.
2 해독IR 해석. 쓸 번지와 값을 준비해요 (MAR ← CC, MBR ← R3의 값 5).
3 실행No action (계산이 없어요).
4 데이터제어신호 Write. 메모리 CC번지에 MBR의 값을 써요 (MEM[CC] ← 5).
5 기록No action (레지스터에 쓸 것이 없어요).

예 3. LOAD R5 CC (스스로 해 보기) — 교수님이 "혼자 해 보라"고 한 명령이에요. 같은 방식으로 따라가면 해독에서 MAR ← CC, 데이터에서 Read로 MBR ← MEM[CC], 기록에서 R5 ← MBR이 돼요. 실행은 No action이에요.

왜 이렇게 쪼갤까요? 5단계는 서로 쓰는 부품이 달라서 신호가 겹치지 않아요. 덕분에 다음 절의 파이프라인처럼 겹쳐서 실행할 수 있어요.

2023년 기출 Q7은 이 그림을 그대로 냈어요. 04번지의 ADD를 실행하는 중이고, 메모리에는 00번지 MOVE R1 5, 02번지 MOVE R2 7이 들어 있었어요(그래서 R1=5, R2=7이에요). 답은 아래와 같아요.

빈칸답어떻게 알아보나
①인출(fetch)그림에 PC, MAR, IR, MBR 화살표가 있으면 인출이에요.
②, ③4, 6PC : 현재 값 ; PC ← 다음 값. 현재 04번지니까 4, 다음 명령은 06번지니까 6이에요.
④4MAR ← PC 값이에요.
⑤ADD R3 R1 R2IR ← 메모리에서 읽은 명령이에요.
⑥실행(execute)ALU, X, Y, 제어신호, AC가 보이면 실행이에요.
⑦+ADD니까 더하기 신호예요.
⑧, ⑨5, 7R1=5, R2=7 값이 X, Y로 들어가요.
⑩125 + 7 = 12이고 AC ← 12예요.

Q6.2도 같은 계산이에요. "1100 0011 0001 0010"(ADD R3 R1 R2)을 ALU에서 계산할 때 R1=2, R2=3이면 입력은 A=0000 0010, B=0000 0011, C=1000 0000, Y=0000 0101이에요. 제어신호 C는 왼쪽부터 +, -, ×, /, &, |, >>, << 순서(C7부터 C0)라서 더하기(+)는 맨 왼쪽 비트만 1이에요. 그래서 1000 0000이에요. Y는 2+3=5를 2진수로 쓴 0000 0101이에요.

외우기 팁

그림 문제는 어느 부품에 화살표가 있나로 단계를 알아봐요. PC·MAR·IR → 인출, X·Y·제어신호 → 해독(또는 실행), AC가 값을 받으면 실행, MAR·MBR에서 메모리로 → 데이터, 레지스터에 값이 들어가면 기록이에요. 계산(ADD, MUL)은 1-2-3-5, 메모리(LOAD, STORE)는 1-2-4-5예요.

시험엔 이렇게 써요

CPU는 하나의 기계어 명령을 인출(fetch), 해독(decode), 실행(execute), 데이터(data), 기록(write back)의 5단계 마이크로 명령으로 나누어 실행한다. 인출 단계에서는 PC의 주소를 MAR에 넣고 메모리에서 읽은 명령을 MBR을 거쳐 IR에 가져오며 PC는 다음 명령의 주소로 변경된다. 해독 단계에서는 제어장치가 IR의 명령을 해독하여 제어신호를 결정하고, 실행 단계에서는 ALU가 계산하여 결과를 AC에 둔다. 데이터 단계는 메모리 접근 명령에서만 MAR 주소와 MBR 사이에 값을 읽거나 쓰며, 기록 단계에서는 결과를 레지스터에 기록한다.

잠깐 확인 — ADD 명령에서 "데이터" 단계는 무슨 일을 하나요? 그리고 PC가 4일 때 인출 후 PC 값은?

ADD는 메모리를 안 쓰는 계산 명령이라 데이터 단계는 No action이에요. 명령이 2칸이라 인출 후 PC는 6이에요.
